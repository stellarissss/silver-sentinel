# 从词库到模型：演进规划

> 前置：`23-白名单与冒充判定落地.md`。本篇是**规划**，不含实现。
> 目标不是「用模型替换词库」，而是**让机器判断这个站是干什么用的**，
> 而不是「它有没有出现某些词」。

## 一、为什么现在的路子到顶了

词库的根本问题不是覆盖率，是**建模对象错了**：它建模「涉老行业的词汇」，
不是「欺诈行为」。实测：

| 站点 | 词库分 | 性质 |
| --- | --- | --- |
| 央视网健康频道 | 0.990 | 正规 |
| 39 健康 / 人民健康 | 0.990 | 正规 |
| 中国养老网 | 0.983 | 正规 |
| 已知诈骗话术样本 | 0.990 | 诈骗 |

**8/25 的正规站得分 ≥0.97，和诈骗样本打平。** 这不是调参能修的——
词表越全，正规站命中越多，排序越差，这是负向的规模效应。

上一轮加的白名单/冒充判定解决的是「冒充政府」这一支，但**不冒充政府的诈骗**
（荐股、保健品、刷单、假投资）仍然只能靠词库，仍然会和正规站混在一起。

## 二、要判的不是「像不像诈骗」，是「这站是干什么的」

这是本轮规划的核心转向。

一个客服 SaaS（53kf）和一个养老诈骗站，词库分可能差不多，但**用途天差地别**：

| 站点 | 用途 | 可判定的结构证据 |
| --- | --- | --- |
| 53kf | 客服 SaaS | 产品页 + 定价表 + 试用表单 + 帮助文档 + 备案主体是科技公司 |
| 论坛 | 内容社区 | 版块列表 + 帖子列表 + 用户中心 + 大量 UGC 分页 |
| 企业官网 | 展示 | 产品/案例/关于我们/联系方式，无表单收款 |
| 电商 | 交易 | 商品列表 + 购物车 + 支付 |
| **养老诈骗** | 引流转化 | 单一 CTA + 表单收集身份证/银行卡 + 二维码进群 + 无备案/伪造备案 |

**「用途明确为正常」本身就是最强的排除理由。** 客服站的用途是卖客服系统，
论坛的用途是让人发帖——这两个判断一旦成立，词库命中了什么都不重要。

所以模型是**两段式**：

```
第一段：site_purpose 多分类
        customer_service / forum / ecommerce / corporate / news / government /
        content / landing_page / app_distribution / unknown

第二段：在 landing_page / app_distribution / unknown 上判 risk
        （这三类才是诈骗的容器；客服站和论坛在第一段就被排除了）
```

## 三、特征体系

现有的取证已经产出 HTML、截图、network、TLS、表单、APK——**这些就是特征源**，
不需要新抓。

### 3.1 结构特征（最便宜、最有效）

| 特征 | 来源 | 为什么有用 |
| --- | --- | --- |
| 文本长度、CJK 字数、段落数 | `page_text` | 纯图落地页 vs 内容站 |
| 链接数、内链/外链比、导航项数 | `page_html` | 论坛/客服站导航复杂，诈骗站通常 <5 个链接 |
| 表单数、输入框数、输入类型（身份证/银行卡/手机号）| `forms` | 收集敏感信息是强信号 |
| 按钮数、CTA 文本种类 | DOM | 单一 CTA（「立即申领」）是落地页特征 |
| 图片数 / 文本比、canvas 数 | DOM | 纯图页 |
| 分页/列表/评论区结构 | DOM | 论坛与内容站的判别 |
| 二维码、微信号、QQ、手机号 | `page_html` | 私域引流 |
| APK 链接、非商店分发 | `apk_links` | 高风险 |
| 第三方域名数、POST 目标 | `network` | 数据外传 |
| 桌面/移动文本量比 | 两次取证 | UA 门禁（`np4w53.cn` 26 vs 423）|

### 3.2 文本特征

- 词库命中向量（现有 917 词的 cluster 计数，**降级为特征而不是分数**）
- 「动作 + 对象 + 承诺」三元组计数（扫码/下载/转账 × 补贴/养老/原始股）
- 句读密度、感叹号密度、数字密度（名额/金额）
- 机构自称（`claim` 的 verdict/agency 数）
- 文本 embedding：`bge-small-zh-v1.5`（90MB ONNX，CPU 单条 ~9ms）

### 3.3 基础设施特征

域名年龄、TLD、注册商、证书签发者/有效期、ASN、同 IP/同证书邻居数、
同模板指纹（HTML simhash）、同备案号域名数（站群）。

### 3.4 视觉特征（条件触发）

只在 `page_text_len < 300` 时跑：截图 OCR（PaddleOCR 轻量版）、
主色、国徽/党徽模板匹配、二维码位置。

## 四、标签从哪来

不新起炉灶，用现有资产：

| 来源 | 量级 | 用途 |
| --- | --- | --- |
| `tier=confirmed` + 官方通报 | 现有 | 正样本 |
| `tier=dismissed` + 人工排除 | 现有 | 负样本（**这是最值钱的**，都是踩过坑的）|
| `claim=fake_site_id/impersonation` | 本轮新增 | 高置信正样本 |
| 白名单命中（政府/媒体/edu） | 13k+ | 高置信负样本 |
| 人工标注 | 300 条起步 | 补 `landing_page` / `unknown` 的灰区 |

**关键：先用弱标签训一个基线，再用它给未标注数据排序，人工只标模型最不确定的
那批（active learning）。** 300 条人工标注能把基线从「能跑」推到「能用」。

## 五、模型选型

| 用途 | 选型 | 理由 |
| --- | --- | --- |
| 用途分类（主） | **LightGBM**，~60 维结构+文本特征 | 毫秒级、可解释（feature importance 能写进报告）、CPU 足够 |
| 文本向量 | `bge-small-zh-v1.5`（ONNX，90MB） | 中文短文本强，CPU 9ms/条，无 GPU 依赖 |
| 少样本兜底 | **SetFit**（8~16 条/类即可训练） | 新骗局类型出现时，不用等大样本 |
| 断言抽取 | Qwen3-0.6B / 规则优先 | 只抽「声称的机构/承诺/动作」，不做分类 |

**不上大模型做分类**：慢、贵、不可解释、结论写不进举报材料。

## 六、分阶段落地

### P0：特征落库（1 周）

- 新增 `features.py`：从 `asset.meta["facts"]` + 证据仓算出 60 维特征，写
  `asset.meta["features"]`（JSON）
- 新增 `silver-sentinel features --rebuild --limit 5000`
- **不改任何判定**。这一步只是把数据攒起来，同时验证特征抽取的稳定性

### P1：离线基线（2 周）

- 导出训练集（`tier` 作标签，排除 reviewed 冲突样本）
- 训 LightGBM 两段式，输出 PR 曲线
- 固定测试集：200 条人工标注（100 正 / 100 负），**只在这个集合上报指标**
- 准入门槛：`precision ≥ 0.90 @ recall ≥ 0.60`，否则不上线

### P2：灰度（2 周）

- 模型只用于**排序与降级**，不直接判诈骗：
  - `purpose=customer_service/forum` 且 `risk < 0.2` → 自动 cold（可解释：用途明确）
  - `purpose=landing_page` 且 `risk > 0.8` → 抬到 watch
- 10% 流量灰度，人工抽检 100 条，比对模型与规则的分歧
- 分歧样本回流成新标注

### P3：文本模型替代词库（可选）

- SetFit 在 `landing_page` 子集上训一个「是否涉老诈骗」分类器
- 与词库并行跑一个季度，比较召回率
- 只有稳定优于词库才切换；词库保留为兜底（模型挂了不能瞎）

## 七、评测与监控

| 指标 | 口径 | 告警 |
| --- | --- | --- |
| precision@watch | 人工抽检 50 条 | < 0.8 告警 |
| 用途分类准确率 | 固定测试集 | 月度回归 |
| 特征分布漂移 | PSI（页面文本长度、链接数）| > 0.25 告警 |
| 模型/规则分歧率 | 每日 | > 20% 说明有一方错了 |

**模型必须能给出理由**：LightGBM 输出 top-3 特征贡献，写进 `discovery_reason`。
举报材料里出现「模型认为可疑」是没用的，必须能说「它收集身份证号、只有一个
申领按钮、无备案」。

## 八、风险

1. **标签噪声**。`dismissed` 里有误排除，`confirmed` 里有少量误判。用
   「多源一致」过滤：只有规则、模型、人工三方都不冲突的样本才进训练集。
2. **分布漂移**。骗子换模板比模型迭代快。对策：模板指纹聚类 + SetFit 快速补类。
3. **可解释性**。监管材料要求可核查事实，模型只能做排序，证据链必须落在
   HTML/截图/网络请求上。
4. **不要一步到位**。词库不能删——CT 流每秒几千域名，没有初筛会把富化配额打爆。
   模型是第二层，不是第一层。

## 九、和现有代码的接口

```
capture → facts（现有）
            ↓
        features.py（P0 新增）→ meta["features"]
            ↓
        model/（P1 新增）
          purpose.py   → site_purpose + 置信度
          risk.py      → risk 概率
            ↓
        triage.decide()：读取 meta["ml"]，只做排序/降级，不覆盖硬判据
```

硬判据（伪造标识码、官方通报、人工确认）永远优先于模型。
模型只在「规则说不清」的灰区起作用——这正好是现在误报最集中的地方。
