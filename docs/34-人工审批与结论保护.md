# 34 · 人工审批与结论保护（v1.16.5）

## 1. 这轮做了什么

生产控制台里积压了 147 条「高度可疑」资产，`reviewed_by` 全为空——机器按设计最多只判到
`high_risk`，确认或排除必须人工终审。本轮用真实浏览器登录控制台，逐条看正文证据、信号、
截图与诱饵标注，把每条写成带依据的人工结论，并处理审批期间新进来的一条高危项，共 148 条。

审批结束后「高度可疑」筛选为 0 项，前排不再被 80 条同模板补贴站占满。

## 2. 审批口径与结果

| 人工判定 | 条数 | 依据 |
|---|---:|---|
| 确认涉诈 | 92 | 冒充政府/部委或涉老会销诱饵，正文、截图、证书证据齐全 |
| 可疑 | 35 | 与黑灰产有关但不是涉老诈骗目标，降级保留追踪 |
| 已排除 | 16 | 正常商业站、反诈资讯站，或词表误命中 |
| 证据不足 | 5 | 只取到 Cloudflare 挑战页或 522 超时，不是目标站内容 |

确认涉诈的 92 条里，89 条是两张证书下的仿冒财政部「2026 年度个人财政补贴」站群，
另外 3 条是暖阳养老平台、欢乐领鸡蛋、汇惠通社保匹配。可疑的 35 条按形态分成体育直播站群、
色情/盗版 App 分发、博彩竞猜、加密货币推广、红包/签到引流五类，都保留为后续找团伙的线索。

## 3. 几个要记住的个案

**暖阳（`nuanyang-website.pages.dev`）**：冒充国家民政部、卫健委建「国家级养老服务平台」，
页面有 APK 下载（`20260828214714.apk`）、宣传片和客服电话。它的入口页曾用「安全检测中心」
空壳伪装，首页一个涉老词都没有。按暖阳案例的口径，分发渠道本身就是证据，不能因为首页
干净就漏判。页面右上角还留着「原型 v2.0」的开发标记，不影响定性。

**资金盘曝光网（`zijinpan.cn`）**：这是反诈预警资讯站，收录 995 个跑路项目档案。正文里
「保本高息」「拉人头」「虚拟币充值」都是被曝光项目的描述，不是本站干的事，词表却把这些
词算成了本站的诈骗信号，给出 69.9 分。页面还带反射型蜜罐（回显一次性探针串），是资讯站
的反爬能力，不是诈骗落地页的特征。按「诱饵和蜜罐要当证据之一」的要求，这条判为排除。

**星驿付（`xingyibao.com`）**：POS 终端招商站，「免费领取」只是产品栏目，被误命中
「免费领鸡蛋引流」。同样带反射型蜜罐，判为排除。

**汇惠通（`huicetong.com.cn`）**：冒充国家惠民政策的「社保待遇智能匹配平台」，备案主体是
个人（余航程），落地页只有登录和注册。判为确认涉诈，但取证只到登录框，没收割链路的
证据，备注里写明了这个边界，后续要补证。

**拦截页 5 条**：`xb-douyin.com` 等只取到 Cloudflare 挑战页或 522 超时。按 `decoy.py` 的
规矩，基础设施拦截页不能当证据判低分，一律列「证据不足」等重试。

## 4. 顺带修掉的生产问题

审批写回去几分钟后，40 条 `confirmed` 被打回 `high_risk`，而且全是伪造政府标识码那批。
查下来是两层原因：

1. `_apply_claim()` 碰到 `fake_site_id` 无条件把判定改成 `high_risk`，压过了 `assess()`
   因为「已人工复核」给出的 `confirmed`；
2. `apply_assessment()` 直接把机器判定写库，没看 `reviewed_by`。

周期研判每轮挑 40 个高分资产重评，于是人工结论一轮一轮被冲掉。

v1.16.5 改了三处：

- `scoring/reassess.py`：`apply_assessment()` 在 `reviewed_by` 非空时只更新分数、置信度
  和信号，不写判定。分数和证据照常刷新，人工结论不动。
- `pipeline.py`：`pending_assets()` 在 SQL 里排除已复核资产，省掉每轮 40 个高分资产的
  白工，也少一些 SQLite 锁竞争。
- `intake.py`：重扫路径同样保护已复核判定，避免没有正文的资产从另一条路被覆盖。

新增 `tests/test_review_protection.py` 三个用例：伪造标识码提级压不过人工确认、未复核资产
仍按机器结论正常落档、已复核资产不进周期研判待办。

## 5. 验证

- 全量测试 515 passed，`ruff check` 无告警。
- wheel `silver_sentinel-1.16.5-py3-none-any.whl` 经 `deploy/push.sh` 部署，服务健康检查
  通过，口令与数据目录未变。
- 重新写回 148 条后逐条校验 `verdict` / `reviewed_by` / `notes`，147/147 一致；跨多个
  周期再查一次，仍是 147/147，没有被回退。
- 控制台「已确认」92 条折成 5 项，「已排除」16 项，「高度可疑」0 项。

## 6. 还没解决的

机器把 35.8 分的站也标成「高度可疑」，说明 `high_risk=40` 的门槛加上 `reassess` 的强制
提级，会让大量体育直播、博彩、色情 App 站混进高危池。这轮靠人工把它们挑出去了，但判定
逻辑本身还没调：要么抬高机器门槛，要么让分数下降时判定跟着回退。下一轮改规则时要连这个
一起处理，否则每跑一天又会攒出一批新的误报高危项。

另外软件/APK 侧资产仍然接近零，外部情报源也弱，已有发现渠道的覆盖面还没打开。
