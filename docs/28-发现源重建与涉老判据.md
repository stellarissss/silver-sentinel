# 发现源重建与涉老判据（v1.11.0 → v1.11.8）

> 2026-11-08 · 承接 `docs/27-运营复盘与重构方案.md` 的路线 A
>
> 一句话：**判定引擎一行没动，只把「从哪找站」和「什么时候该报给人」换掉了。**
> 上线当天，同一个系统从「0 条涉老」变成「3 条 Watch，其中 2 条 P0」。

## 一、改了什么

| 文件 | 改动 | 为什么 |
|---|---|---|
| `discover/harvest.py`（新增） | urlscan 标题检索，5 类话术 29 个查询词 | CT 只认域名里写了什么，涉老域名是随机串 |
| `discover/engine.py` | 新增 `_harvest_loop`，与 CT 并列 | 外部线索走同一条落库路径，不另起炉灶 |
| `capture.py` | `source_rank` 排序；接入涉老判定 | 已被人在页面上见过话术的，优先取证 |
| `elder.py`（新增） | 四要素判定：受众/身份/权威/动作 | 「涉老」不是「黑产」的子集，得单独算 |
| `triage.py` | P0 直通 Watch，且排在用途闸门**之前** | 涉老落地页结构上就是 landing，闸门会把它筛掉 |

**没有动的**：评分引擎、词库、白名单、用途模型、`claim` 判定。
真实样本喂进去本来就判 95 分——问题从来不在那里。

## 三、判据细节

### 3.1 查询词必须是话术，不是行业词

实测对照：

| 查询 | 返回 | 有用吗 |
|---|---:|---|
| `page.title:"养老"` | 82 条 | 全是养老院官网、管理系统、大学学院 |
| `page.title:"个人财政补贴"` | 3 条 | 全是同模板诈骗站 |

所以词表按话术簇组织（`subsidy` / `unfreeze` / `pension_invest` / `health` / `social_security`），
每簇 4–8 个词，一轮跑 4 个、按顺序轮换，避免触发限流。

加词前的规矩：**先跑一遍，看返回的是养老院还是诈骗页**，把结果写进注释。

### 3.2 保留完整主机名，不归并到注册域

CT 那条路必须 `collapse_host`（它只给域名）。这里不能：

- `s.qka91.com` 是民族资产解冻的落地页
- `qka91.com` 可能压根没建站

归并过去等于把唯一入口弄丢。测试里有一条专门守这个。

### 3.3 涉老四要素

```
audience  受众指向  养老/退休/社保/医保/补贴 + 民族资产解冻这类专盯老人的骗局
identity  身份索取  身份证/银行卡/社保卡/人脸/验证码（或表单里有对应输入框）
authority 权威冒用  claim 判出 fake_site_id / impersonation，或正文写了部委名
action    转化动作  下载 APK / 加微信 / 扫码 / 限时领取
```

- `audience` 是必要条件（否则赌场也算涉老）
- 凑 2 条 → 涉老（P1，留候选池）
- 凑 3 条且含 identity 或 authority → **P0（直通 Watch）**

判错的代价不对称：多报一条只是多一次人工复核，漏报是有人当天被骗走养老钱。
所以阈值往宽了取。

### 3.4 涉老必须排在用途闸门之前

这是本轮最容易踩的坑。涉老诈骗的落地页在结构上就是 `landing`——
单页、有 CTA、没有导航。用途闸门看到 `landing` 会判「经营型落地页」，
置信度还不低（`huicetong.com.cn` 就是 0.85）。

闸门在前，等于把目标本身筛掉。所以 `triage.decide` 里涉老判断放在
`_purpose_gate()` 之前，P0 直接 return Watch。测试
`test_purpose_gate_cannot_suppress_elder_target` 守着这条。

## 四、开关与回退

```bash
SILVER_HARVEST_ENABLED=1          # 默认开
SILVER_HARVEST_INTERVAL=3600      # 一轮间隔（秒）
SILVER_HARVEST_QUERIES=4          # 一轮跑几个查询
```

关掉外部源：`SILVER_HARVEST_ENABLED=0` 重启 worker，发现层退回纯 CT。
关掉涉老提级：暂无独立开关——`elder` 只写 `facts`，不改分；
要停就改 `triage.decide` 里那一段（已用注释标出）。

## 五、已知边界

1. **urlscan 覆盖率有限**。它只索引被提交扫描过的页面，长尾诈骗页未必在里面。
   短链展开、举报线索、模板指纹扩散都还没做，是下一步。
2. **配额**。免费 API 有速率限制，一轮 4 个查询 + 2.5 秒间隔是保守取值。
   词表 29 个查询跑完一轮要 7 个多小时，实际轮换下来每个词一天跑 1–2 次。
3. **`l4k9j.com.cn` 这类半死站抓不到**。取证超时是站点本身的问题，
   不是发现层的问题——但确实会漏。
4. ~~APK 只下载不解析~~ —— v1.11.2 已补：落盘前调 `apk_collector.analyze()`，
   包名/危险权限/无障碍/签名写进 `meta["apk_analysis"]`，并作为 hard evidence 提级。
5. **P1 没有独立队列**。现在 P1 只是「不进冷存 + 进候选」，前端还看不到这个字段。
6. **`xinjianggongjijin.com` 这类「代办提取」灰产判不出来**。它页面上没有冒充、
   没有身份证表单，只有「代办」两个字。这类需要单独的「声称能办你办不成的事」
   判据，留到下一轮。

## 六、上线后的调优：三轮误报收敛

第一版把涉老判据接进去，生产库立刻多出 6 条 `elder=True`，其中 **3 条是误报**。
每一轮都是拿真实误报反推词表边界，不是拍脑袋调阈值。

| 轮次 | 误报 | 根因 | 修法 |
|---|---|---|---|
| 1 | `baidu-ads.com`（百度广告代理） | `免费领` 被当受众词，实际是营销动作 | 挪到 `_ACTION`，受众词只留「这是给谁的」 |
| 2 | `tuiyijunren.cn`（退役军人资讯站） | 「受众 + 营销动作」就判涉老，而这是所有营销页的写法 | 必须有**冒充权威**或**索取身份**才成立 |
| 3 | `tuiyijunren.cn` 仍中招 | 「办事要带身份证」被当身份索取 | 只认「填写/输入/上传/绑定 + 证件」的语境 |
| 4 | `meituanshangjiabandenglurukou.shop`（仿冒美团） | 「登**录入**口支持短信验证码」被正则切开 | 去掉「录入」，去掉「短信验证码」独立分支 |
| 5 | `tuiyijunren.cn` 再次中招 | 正文引用「根据民政部规定」被当冒充 | 权威只认 `claim` 的结构化判定，正文兜底要求同时出现「审核/主导/授权」 |

最终生产库：**涉老 4 条，全部是真诈骗，零误报**。

```
np4w53.cn                     watch  95.0  P0  伪造标识码 + 补贴 + 倒计时
hksm38.com.cn                 watch  95.0  P0  同上（同模板）
nuanyang-website.pages.dev    watch  70.0  P0  冒充民政部 + 分发 APK
s.qka91.com                   watch  70.0  P1  冒充国务院办公厅
```

调优过程本身说明一件事：**「涉老」不能用行业词判**。
「养老」「补贴」「身份证」「民政部」在正规站里全都出现，
判据必须落在**行为**上——谁在冒充、谁在要证件、谁在让人马上下决定。

## 七、APK 链路的第二个坑：10MB 阈值

`_download_apk_locked` 里候选档的 `max_mb = 10`，而 `nuanyang` 的包是 **16.5 MB**。
取证发生在判级之前，那时 tier 还是 candidate，于是包被直接拒。

```
16.5 MB > 10 MB  →  "超过单包上限"  →  证据目录里什么都没有
```

改成 50MB（由每日 300MB 配额兜底）。重抓后：

```
sha256   deea5c2d2f7e275a...
包名     com.nuanyangcare.app
危险权限 6 项
无障碍   True
权限     INSTALL_PACKAGES / QUERY_ALL_PACKAGES /
        ACCESS_BACKGROUND_LOCATION / READ_PHONE_STATE / ...
```

有 `INSTALL_PACKAGES` + 无障碍服务，意味着这个包能读短信拿验证码、
能替用户点确认、能再装下一个包。这条证据比页面话术硬得多，
所以 `triage` 里给它开了直通 Watch：**高危安装包本身就是充分条件**。
