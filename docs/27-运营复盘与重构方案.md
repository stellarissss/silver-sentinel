# 运营复盘：为什么抓不到涉老，以及该拆哪里

> 2026-11-08 · 基于生产库 4,311 条资产与 5 个真实涉老样本的端到端实测
>
> **结论先行**：判定引擎是好的，发现层是坏的。
> 把 5 个真实涉老诈骗站手工喂进系统，4 个当场判出 95/95/70/70 分进 Watch，
> 其中一个 16.5 MB 的 APK 被完整下载落盘。
> 但这 5 个站在生产库里的记录数是 **0**。
> 系统不是"判不出来"，是"从来没看见过"。

## 三、四层断点，逐层定位

### 断点 1：发现层用「域名语义」做漏斗

`discover/keywords.py` 的词库是给**域名**用的：中文词 + pypinyin 派生变体，
`discover/engine.py:COLD_THRESHOLD = 0.30`，低于这个分数进冷存、永不取证。

- `np4w53` → 去数字得 `npw` → 匹配不到任何词 → 0 分 → 冷存
- `hksm38` → 同理
- `l4k9j` → 同理

**而这恰恰是这批站的共性：域名是随机的。**

它们是靠短信、微信群传播的，不需要一个好记的域名。域名对它们只是"用完就扔的地址"。

反过来，能命中词库的域名（`yanglao-xxx`、`gongjijin-xxx`）才是少数。
词库这道漏斗，天生只放行"把意图写进域名"的站——也就是站群。

实测印证：4 天 4,311 条里，79%（3,413 条）来自 CT 日志，
产物是博彩、盗播、盗版——全是靠域名当招牌的生意。

### 断点 2：取证只抓首页，且 56% 根本没抓

```
captured 1,289 (29.9%)   failed 542 (12.6%)   pending 2,432 (56.4%)
```

失败原因 top：`端口无法连接` 354 条、`Page.goto 超时` 78 条。

待抓的 2,432 条不是"排队中"，是**永远不会轮到**——队列按分数排序，低分的沉底。

即便抓了，也只抓首页 DOM。涉老诈骗的关键信息在：

- 表单**字段语义**（要身份证 / 银行卡 / 验证码 / 人脸）
- 提交后的**下游页面**
- 二维码背后的**微信/短链**

这三样，现在的采集器都不看。

### 断点 3：APK 能力齐全，但线上从不触发

代码是有的：

- `collectors/apk_fetch.py` — 下载器，`candidate_links()` 从页面挑 `.apk`
- `collectors/apk.py` — manifest 解析，输出包名/权限/签名
- `capture.py:1080 _download_apk_locked()` — 取证时调用

但触发条件是 `intake.py:248`：

```python
if any(h in corpus for h in DOWNLOAD_HINTS) or ".apk" in url.lower():
    facts["forces_apk_download"] = True
```

`corpus` 来自**用户输入或首页文本**。线上 4,311 条资产全部由 CT/旁站自动发现，
文本为空 → `forces_apk_download` 恒为 False → APK 链路静默不触发。

手工喂 `nuanyang-website.pages.dev` 时它确实跑了，16.5 MB 落盘、sha256 记录，
但**没有解析 manifest**——保存了文件，没读权限和包名。

顺带一个 bug：`apk_links` 的正则把 `.zip` 也算作安装包。
`mathjax.org` 的源码包、`mux.com` 的 press kit 都进了这个字段。

### 断点 4：判级里没有「涉老」这个维度

现在的分数回答的是「**像不像黑产站群**」：
域名新注册、无备案、便宜 TLD、威胁情报命中、词库密度。

这解释了为什么产出全是博彩盗播——它们完美符合这套画像。

但「涉老」不是这套画像的子集。涉老诈骗的画像完全不同：

| 维度 | 站群/博彩 | 涉老诈骗 |
|---|---|---|
| 域名 | 批量注册、语义化 | 随机、单个、用完即弃 |
| 生命周期 | 数月 | 数天到数周 |
| 入口 | 搜索引擎、导航站 | 短信、微信群、熟人转发 |
| 载体 | 网页 | APK、H5、小程序 |
| 核心动作 | 注册充值 | 填身份证/银行卡/人脸 |
| 收益 | 赌资 | 盗刷 + 身份数据转卖 |

用前者的画像去筛后者，越调越偏。

## 四、为什么这不是调参能救的

三条路都试过了：

1. **加词**——词库已含"以房养老""养老基金""民族资产解冻""免费领鸡蛋"，
   但域名不叫这些，词库在发现层根本用不上。
2. **降阈值**——把 `COLD_THRESHOLD` 从 0.30 降到 0，等于全量取证。
   CT 每天数百万条，2G 内存的机器一天抓不完 1%，队列彻底堵死。
3. **加情报源**——urlhaus/openphish 已接入，但它们收录的是
   **已被举报的钓鱼站**，涉老诈骗从被举报到关站常常不到 48 小时。

根因是**漏斗的入口错了**：用域名筛，而目标恰好不用域名。

## 五、重构方案

### 路线 A：换发现源（1–2 天，验证可行性）

保留判定引擎（已证明 95 分可用），只替换"从哪找站"：

| 渠道 | 做法 | 已验证 |
|---|---|---|
| 标题倒查 | `urlscan.io` `page.title:"补贴申领"` → 直接命中 np4w53/hksm38/l4k9j | ✅ 本轮实测 |
| 模板指纹扩散 | HTML 结构 hash / favicon hash / 静态资源路径 hash 找同伙 | 待做 |
| 短链展开 | t.cn / url.cn / dwz 展开后取落地域名 | 待做 |
| 举报线索 | 12337、各地反诈通报里的域名/号码 | 待做 |

预期：第一天就能把真实涉老站送进 Watch。

代价：依赖第三方 API 配额；urlscan 免费额度有限，需要自建或换源。

### 路线 B：目标重定义 —— 从「扫描器」到「鉴定器」

系统不再假设"我能扫遍全网"，而是承认：

> 涉老诈骗的入口是一条短信、一个微信群链接、一个安装包。
> 我们拿到的不是"全网"，是"某个人正在看的那个页面"。

产品形态变成：**输入一条链接/一个 APK/一张截图 → 输出是不是涉老诈骗 + 证据链**。

发现交给外部（家属举报、社区网格员、运营商短信网关）。
系统的价值在于"判得准"，而不是"扫得广"。

这条路更贴近真实使用场景，但要改前端和交互。

### 路线 C：全量重建（A + B + 判据重构，2–3 周）

在 A、B 基础上，把「涉老」做成一等判据，四要素合取：

```
涉老 = 年龄指向（养老/退休/社保/医保/补贴/银发/爸妈）
     ∧ 身份索取（身份证/银行卡/人脸/验证码）
     ∧ 权威冒用（部委/国徽/标识码/文件号）
     ∧ 转化动作（加微信/下载 APK/填表/限时倒计时）
```

配套改造：

- 取证：强制表单字段语义分析、APK 必解析 manifest、下游页面跟进
- 队列：涉老 P0（人工即看）/ 其他黑产 P2（归档）
- 证据：截图 OCR，抓"国徽 + 红头 + 文号"这类视觉特征

### 推荐顺序

**先 A 证明可行，再 B 改产品形态，最后按实际数据决定 C 的范围。**

理由：A 只需要 1–2 天，且能立刻回答"我们到底能不能抓到真站"。
如果 A 跑一周仍抓不到 10 个真实涉老站，说明问题比发现层更深，C 也救不了。

## 六、验收标准（重构后必须满足）

| 指标 | 改造前 | 改造后（v1.11.8） | 目标 |
|---|---:|---:|---:|
| 真实涉老样本召回 | 0/5 | **4/5**（`l4k9j` 站点半死） | ≥ 8/10 |
| 涉老进 Watch | 0 | **4**（3 P0 + 1 P1） | — |
| Watch 档里涉老占比 | 0% | **50%** | ≥ 60% |
| 真实 APK 落盘 | 0 | **1**（16.5 MB，6 危险权限，无障碍） | ≥ 5/周 |
| 误报：正规站被判涉老 | 未测 | **0**（5 轮收敛） | 0 |
| 从"站点上线"到"进 Watch" | 不可达 | ~2 分钟（发现→取证→判定全自动） | ≤ 48 小时 |

第一条是硬门槛。达不到就不算"可行"。
