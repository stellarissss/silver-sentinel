# 基础设施扩散与形态预筛（v1.12.0）

> 上一版把发现层从「只认域名关键词」补到了「也认页面标题」。这一版解决的是
> 更根本的问题：**urlscan 的标题索引里，中文涉老话术总共只有几十条**。
> 靠它做「广泛发现」，天花板就是几十条。

## 一、先把天花板量出来

2026-11-08 把词表里 49 个话术词全部跑了一遍 `page.title:"…"`，命中数写在下面。
这个数字决定了任何「加词」的努力值不值得。

| 簇 | 词 | 命中 |
|---|---|---:|
| subsidy | 个人财政补贴 / 补贴申领 / 财政补贴 | 3 / 4 / 3 |
| subsidy | 惠民资金 / 惠民补贴 | 1 / 1 |
| subsidy | 养老金补发 / 社保补贴 / 高龄津贴 / 扶贫款 / 补贴领取 / 国家补贴 / 专项补贴 / 发放补贴 | **0** |
| unfreeze | 民族资产解冻 / 资产解冻 / 国家项目 / 解冻费（共 6 词） | **0** |
| pension_invest | 智慧养老平台 / 老龄康养 / 养老投资 / 康养中心 | 1 / 1 / 1 / 2 |
| health | 免费领鸡蛋 | 1 |
| health | 健康讲座 / 特效药 / 专家义诊 / 名医坐诊 / 免费体检 / 祖传秘方 | **0** |
| social_security | 社保卡异常 / 社保账户 / 医保补贴 / 电子社保卡升级（共 8 词） | **0** |
| gov_spoof | 民政部 | 1 |

结论有三条：

1. **「民族资产解冻」「社保卡异常」这类词在标题里根本不出现**。骗子写标题时
   要的是「像一条通知」，不是「像一个骗局」。用骗局的名字去搜，必然为零。
2. **有效的词只有 11 个，全量跑一天也只能捞到 20 来条**。而且高度集中在同一
   个模板（`2026年个人财政补贴申领` 占了 12 条）。
3. **搜索引擎这条路也是死的**。用必应搜 `"2026年个人财政补贴申领"`，返回的
   全是日历站和 gov.cn 通稿——诈骗站被安全厂商拉黑，或者本来就没做 SEO，
   入口是短信和微信群。

所以「广泛」不能靠「更会搜」，只能靠**换物理量**：从「谁写了这个话术」换成
「谁和已知的站共用基础设施」。

## 二、拿到一张证书，等于拿到一窝

关键实测（`discover pivot l4k9j.com.cn`）：

```
l4k9j.com.cn 的一张证书，SAN 里有 30 个域名
  a7k2m.com.cn  b3t8n.com.cn  c2r7h.com.cn  ... z7x4c.com.cn
  全部 .com.cn、全部同日签发（2026-10-08）、全部同一个生成器
```

这 30 个域名在本系统改造前的生产库里**一条记录都没有**。不是判不出来——
把 `np4w53.cn` 喂进判定引擎能打 95 分——是从来没见过。

对 `hksm38.com.cn` 做同样的操作，带出另一批 9 个：

```
bncp24  gtds85  jrfy47  mdyj91  pqzv19  tfbx42  vwlr73  xmwk62  zqtn56
```

抽查 4 个，全部在线，标题**逐字相同**：`2026年个人财政补贴申领`。

一个线索进来，九个站出去。这才是「广泛」的量级。

### 为什么不用 crt.sh

`crt.sh` 对 `.cn` 域名经常返回 0 条（`l4k9j.com.cn` 就是 0），而 CertSpotter
直接从 CT 日志取，同一次签发能拿到全部 30 个 SAN。对国内站群来说，这个差别
是「全有」和「全无」。

免费额度 100 次/小时，够用：一次扩散能带出 9~30 个域名，一小时查 60 次就
覆盖 500+ 个新域名。

### 收敛性

把 9 个兄弟域名逐个再查一遍证书，全部回到同一批 10 个域名——**证书就是批次
边界**。所以这个扩散是收敛的，不会指数爆炸，也不会漏出批次。

## 三、形态学：让 CT 全量流有用

CT 日志每天几十万个新域名，词库只能筛出「名字里写了什么」。而站群域名是
批量生成的随机串，词库天生看不见。

`discover/morph.py` 只做一件事：给域名打一个「像不像批量生成」的分。

| 域名 | 分 | 依据 |
|---|---:|---|
| np4w53.cn | 0.92 | 数字夹在字母中、几乎无元音、字母数字混排 |
| hksm38.com.cn | 0.92 | 同上 |
| l4k9j.com.cn | 0.92 | 同上 |
| s.qka91.com | 0.74 | 取注册域标签 `qka91`，元音稀少 |
| huicetong.com.cn | 0.00 | 纯字母、含常见音节 |
| laoweimin.cn | 0.00 | 纯字母、可读 |
| ryylchina.com | 0.15 | 纯字母、元音稀少 |
| rong-guangdong.com | 0.05 | 含分隔符 |

正例最低 0.74，负例最高 0.31，**间隔 0.43**。阈值取 0.62，不是硬凑的。

### 只排序，不定罪

形态分高的域名不会直接进库。CT 里「词库没命中但形态分 ≥ 0.62」的先进一个
内存池（上限 4000），由 `_shape_loop` 每 25 秒取 90 个做 DNS。

**只有解析到已知涉老 IP 的才升级**。理由：CT 每天几万个随机串，全抓页面等于
自己造一个分布式扫描器，既慢又打草惊蛇。DNS 查询不进对方 web 日志，30 QPS
能覆盖全量，成本几乎为零。

## 四、IP 池：一台服务器比一万个域名值钱

域名是一次性的，被骗的人举报一个就换一个；服务器不是。

`np4w53.cn` 与 `hksm38.com.cn` 同 IP `204.194.55.233`、同 ASN `AS140869`。
所以「新域名解析到了已知涉老 IP」这条信号，比任何文本特征都硬。

池子只收**危害已明确**的资产（`elder.priority == P0` 或 `apk_danger` 或
`tier == confirmed`）。普通 watch 不能进——生产库 8 条 watch 里有 4 条是反诈
曝光站、广告站、代办灰产，把它们放进去等于往池里倒噪声。

排除共享设施是硬门槛：Cloudflare、阿里云、AWS、Fastly 的 IP 一律拒绝。
`nuanyang-website.pages.dev` 的两条 IP 都在 Cloudflare，实测被正确挡在池外。

还有一条不花钱的：**本地被动 DNS 反查**。我们为别的目的查过的 DNS 缓存，
反过来就是一张「谁和谁同服务器」的表。`DNSCache.reverse(ip)` 直接遍历，
不需要任何外部 API。

## 五、App 分发站：两道门

`26537.net`（暖邻，浙ICP备2026095006号）是这轮最有价值的样本。

```
GET /            → 「安全检测中心」假页，3 秒后自动跳转
GET /download    → 真正落地页，两个下载按钮
GET /go/download1 → 302 → sdsd2sdu-62hdiigx.zrudqa.cn/pqkfeoc.apk（80MB）
GET /go/download2 → 302 → sdwdxsgx.zrudqa.cn/pqkfeoc.apk（同一文件）
```

暴露了两个此前完全看不见的漏洞：

**洞一：只认 `.apk` 结尾的链接。** 按钮是 `<a href="/go/download1">`，
不以 `.apk` 结尾，`_APK_URL_RE` 打空，`apk_links` 为空，于是「页面没有安装包」。
线上「一个 APK 也没有」，有一半是这么来的。

修复：`web.py` 增加 `_looks_like_download_entry()`，把 `/go/ /dl/ /download/
/app /apk /get` 这类路径也收进候选，排在真 `.apk` 之后（它们要多跳一次才
知道是不是包）。实测立刻识别出 5 个入口：`/go/download1 /go/download2
/go/line1 /go/line2 /go/line3`。

**洞二：包解析失败被当成「干净」。** 这个 80MB 包把 `AndroidManifest.xml`
做成了一个**目录**，里面塞几百个假 xml 当诱饵；真 manifest 改名成大写
`ANDROIDMANIFEST.XML` 放在根目录，并加密。按名字取第一个候选会拿到加密块，
解析出 0 权限、0 危险权限，`apk_danger = False`。

修复两处：
- `_locate_manifest()`：枚举全部同名候选，按体积升序逐个试，取第一个能解析
  出包名的；全部失败则标记 `manifest_obfuscated = True`。
- `triage`：`apk_unparsed`（对抗静态分析）与 `apk_too_large`（超上限没下来）
  都算「无法确认」，进候选池而不是冷存。**解析不出来 ≠ 干净。**

## 六、验收

同一天、同一个生产库，改造前后对比：

| 指标 | v1.11.8 | v1.12.0 |
|---|---:|---:|
| 涉老资产总数 | 4 | **12** |
| 其中 95 分（伪造政府标识码） | 2 | **10** |
| cert_sibling 来源资产 | 0 | **18** |
| ip_pool 来源资产 | 0 | **9** |
| 同源扩散条数（累计） | 0 | 45 |
| 形态池 → DNS → IP 命中 | 0 | 4 |
| 正规站被判涉老 | 未测 | **0** |

具体落地（全自动，无人工喂样本）：

```
18:27:05  IP 池更新：4 个新 IP，池内 3 条
18:27:07  同源扩散：np4w53.cn 带出 1 个域名
18:27:10  同源扩散：hksm38.com.cn 带出 10 个域名
18:27:12  同源扩散：nuanyang-website.pages.dev 带出 4 个域名
```

8 个新域名走完取证 + 判定，全部 95 分进 watch，理由一致：
`伪造政府网站标识码 bm01000001（该码只发给 .gov.cn）`。

### 形态池的实测

启动 20 分钟（CT 追了 1.1 万条）：

```
shape_seen      113   词库没命中、但形态分 >= 0.62 的域名
shape_resolved  103   解析出 A 记录的（91%，符合随机串域名大面积启用的特征）
ip_hits           4   落到已知涉老 IP 上的
```

4/103 这个比例是对的：随机串域名大部分是正常业务（短链、测试、内部系统），
只有落到涉老 IP 上的才是同批货。**精度来自 IP，不来自形态**——形态只负责
把 10 万条压到 113 条，让 DNS 这一步变得免费。

### 已知缺口

- **同 IP 扩散会带噪声**。`221.228.32.13` 上除了 `xmwk62.com.cn`，还挂着
  黄播站（`hsck5go.wiki`、`25kkxx.vip`）、赌博站（`ywxn56.buzz`）
  和一堆看不出业务的域名。它们确实在黑产 VPS 上，但对「涉老」这个目标是噪声。
  现在全部进候选池、取证后按内容判定降级，不占 watch。
- **80MB 的包还是下不来**。磁盘只剩 6.9G，日配额 300MB 的制度下不敢放开。
  现在只记录 `apk_too_large: {size_mb: 80}`，并把这句话写进 discovery_reason，
  人工取样。
- **`l4k9j.com.cn` 这批已下线**。30 个域名里抽查的 4 个全部连接失败，
  资产入了库但取证会失败，属于「知道但拿不到证据」。这类只能等它们重新启用。
- **pivot 的判据收窄过一次**。第一版条件里带了 `apk_danger`，结果把
  `apidevel.org`（印尼赌博站，一个无障碍权限就够）当成扩散源，一次拉进 35 个
  子域（`bio./cdn./admin./pixel.`）。现在只对 `elder=True 且 P0/P1` 扩散。

## 七、怎么用

```bash
# 手工扩散（最有用的排查动作）
silver-sentinel discover pivot hksm38.com.cn

# 带上同 IP
silver-sentinel discover pivot hksm38.com.cn --ip 204.194.55.233

# 看扩散在后台跑了多少
silver-sentinel discover status | jq .stats | grep -E 'pivot|shape|ip_'
```

回退开关：

| 开关 | 效果 |
|---|---|
| `SILVER_HARVEST_ENABLED=0` | 只剩 CT + DNS，丢掉外部线索 |
| 注释 `engine.py` 里 `_offer_shape` 调用 | 关掉形态预筛，CT 回到纯词库 |
| 清空 `data/bad_ips.json` | IP 池归零，同 IP 扩散失效 |
| `data/harvest_state.json` 里的 cursor | 查词进度，删了会从头开始 |
