# 判定规则与评分模型

> 规则库：`src/silver_sentinel/rules/builtin.yaml`（42 条，声明式 YAML，改规则不用改代码）

---

## 一、为什么不用「加权求和」

最朴素的做法是给每条特征打分再相加。它会立刻退化成两个问题：

1. **弱信号淹没强证据**。「免费领鸡蛋」18 分 + 「使用 .top 域名」6 分 + 「页面有下载按钮」14 分 …… 凑够十条就能超过「携带读取银行验证码短信的权限」这一条铁证。
2. **分数无上界**。要么硬截断到 100（丢失区分度），要么出现 180 分这种无法解释的数字。

本项目采用 **noisy-OR**（独立证据的概率并集）：

```
risk = 1 − Π (1 − wᵢ/100 × cᵢ)
```

其中 `wᵢ` 是规则权重，`cᵢ` 是我们对这条规则可靠性的把握（confidence）。

它的性质正好符合证据直觉：

- 单条 18 分 → 18 分
- 两条 18 分 → 32.8 分（不是 36）
- 十条 18 分 → 86 分（不是 180，也不会溢出）
- 每条信号的**边际贡献递减**，后来的证据必须提供新信息才有意义

**跨维度加成**：当命中覆盖 ≥ 4 个独立维度（分发 / 冒充 / 资金 / 话术 / 技术 / 信誉）时，分数 × 1.08。理由是一个骗局同时具备"怎么送到手机上""冒充谁""怎么收钱""怎么说话"四层特征时，它是同一套剧本的概率远高于四个孤立特征碰巧同时出现。

## 二、置信度是独立的一维

```
confidence = (1 − Π(1 − cᵢ)) × min(1, 0.45 + 0.12 × 独立来源数 + 0.06 × 维度数)
```

分数回答「有多像」，置信度回答「证据够不够」。

系统**允许弃权**：命中信号少于 2 条时，无论分数多少都返回 `insufficient`（证据不足），而不是硬给一个结论。一个只会说"可疑"的工具，用两次就没人信了。

## 三、五档判定与那道不可逾越的线

| 判定 | 条件 | 处置建议 |
| --- | --- | --- |
| `insufficient` 证据不足 | 信号 < 2 条，或分数 < 15 | 补充材料后重判 |
| `low` 低风险 | 分数 < 15（且 ≥ 2 条弱信号） | 观察 |
| `suspicious` 可疑 | 15 ≤ 分数 < 35 | 暂停付款与实名，反向核实 |
| `high_risk` 高度可疑 | 35 ≤ 分数 < 70，或 ≥ 70 但无官方/人工背书 | 进入处置队列 |
| `confirmed` 确认涉诈 | **官方通报命中** 或 **人工复核** | 立即举报、劝阻、止付 |

**机器最高只判到 `high_risk`。**

这是整个系统最重要的一个约束。反诈工具误伤一个正常应用的代价（名誉、投诉、信任崩塌），远高于漏报一次的代价。所以 `confirmed` 只能由两种东西授予：官方公开通报，或者人。

实现上，即使分数 93 分、命中 9 条信号，只要没有官方名单或人工复核，输出仍是：

```
分数已达到确认档，但缺少官方通报或人工复核，按保守原则降级为高度可疑
```

## 五、可解释性：每条结论都能回到原文

引擎在求值时收集实际命中的词或正则匹配片段，回填到 `detail` 字段：

```
[DIST-008] 指导关闭安全检测
  命中「忽略风险、继续安装」。主动教用户绕过系统安装防护，正规应用不会提出此类要求。
```

事实类规则（如域名年龄、品牌相似度）没有原文可引，则展示判定值：

```
[IMP-004] 品牌相似域名
  判定值：域名 kuaishou-yinfa 在品牌词「kuaishou」上附加「yinfa」。域名在品牌词上做拼接…
```

没有这一步，规则引擎就只是个黑箱；有了它，用户能自己判断这条依据站不站得住。

## 六、加一条规则

```yaml
- id: PER-009
  category: persuasion
  title: 以「国家发放」名义要求先缴费
  weight: 22
  confidence: 0.85
  when:
    all:
      - text_any: [国家发放, 国家补贴, 惠民补贴]
      - text_any: [先交, 缴纳, 手续费, 工本费]
  detail: 财政资金发放不存在"先缴费"环节，凡要求先付费的一律为诈骗。
  cite: 多地反诈中心统一提示
```

支持的条件原语：

| 原语 | 说明 |
| --- | --- |
| `text_any` / `text_all` | 语料中包含任一 / 全部词（自动做 NFKC 归一与零宽字符清除） |
| `text_regex` | 正则匹配 |
| `fact` + `op` + `value` | `eq / ne / gt / gte / lt / lte / in / contains / truthy / nonempty` |
| `indicator` | 针对抽取出的指标列表（手机号、钱包、包名等） |
| `all` / `any` / `not` | 任意嵌套 |

外挂规则（按 `id` 覆盖同名内置规则）：

```bash
SILVER_RULES_PATH=./my_rules.yaml silver-sentinel scan url ...
```

## 七、阈值怎么标定的

不要拍脑袋。用一批**已知结论**的样本回算：

| 样本 | 应得判定 | 校准前 | 校准后 |
| --- | --- | --- | --- |
| 「国惠民生」App 宣传 | confirmed（官方通报） | 53.2 | 72.0 ✅ |
| 民族资产解冻 + 云数贸 + 张健 | confirmed（官方通报） | 38.5 | 72.0 ✅ |
| 快手银发 + 国补 + 关安全检测 | high_risk | 58.5 | 58.5 ✅ |
| 免费领鸡蛋 + 专家义诊 + 根治三高 | high_risk | 31.8 | 37.3 ✅ |
| 社区免费量血压通知 | insufficient | 16.2 ❌ | 0.0 ✅ |

校准过程中修掉的三个真问题：

1. **`unknown` 被当成「非商店分发」**。纯文本资产没有分发信息，默认值 `unknown` 命中了 `distribution_channel in [sideload, qr, link, unknown]`，导致一条正常通知也拿到 16 分。修正：`unknown` 不参与判定。
2. **官方通报被最小信号数卡住**。只有一条「命中官方通报」但信号数 < 2，被判成"证据不足"。修正：官方/人工复核分支提前，不受 `min_signals` 约束。
3. **文本类资产的标题被丢弃**。`kind=text` 时用 `value` 覆盖了 `text`，「惠民补贴申领中心」这种名字里的关键词全丢了。修正：语料 = 名称 + 正文。

这三条都写进了 `tests/`，防止回归。

## 八、误报与漏报的取舍

| 场景 | 系统的选择 | 理由 |
| --- | --- | --- |
| ICP 查不到 | 视为"未知"，**不加分** | 无公开 API，硬判会大面积误伤 |
| LLM 不可用 | 弃权，只用规则 | 宁可少一层叙事，不要一层幻觉 |
| 只命中一条强信号 | `insufficient` | 一条证据不足以定性 |
| 分数 ≥ 70 但无官方背书 | `high_risk` | 机器不授予"确认" |
| 品牌名完全一致 | 不判仿冒 | 可能是真官方，交给其他信号 |

一句话：**在不确定的时候，明确地说不确定，比给一个漂亮的错误答案有用。**
