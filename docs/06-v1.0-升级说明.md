# v1.0 升级说明

> 从「拿线索来查」到「挂在服务器上一直盯着」。
> 本文记录这一版改了什么、为什么这么改、怎么验证它真的能用。

---

## 一、这版要解决什么问题

v0.1 是个称手的现场工具：输入一个链接或安装包，几秒内给出判定和举报材料。
但它有三个结构性缺陷，决定了它没法长期跑：

| 缺陷 | 后果 |
| --- | --- |
| 发现只能靠一个关键词去 crt.sh 查 | 覆盖面窄、延迟高、词库贫瘠（「国科」「中科」这类没覆盖） |
| 判定要求「分数够高才入库」 | 早期线索（域名刚注册、还没挂内容）全被丢，等它火起来已经晚了 |
| 证据只存在数据库里 | 数据库损坏或被删，等于什么都没发生过 |

v1.0 针对这三点重做了发现层、引入了分级与图谱、并把证据落到「只追加 + 异地副本」。

## 二、发现层重做

### 2.1 三路冗余，任何一路挂了不影响其余

| 通路 | 文件 | 说明 |
| --- | --- | --- |
| CT 日志直连 | `discover/ct.py` | RFC 6962：`get-sth` 拿 `tree_size`，`get-entries` 拉条目，`cryptography` 解析 DER 取 CN/SAN。游标落盘，重启续跑 |
| certstream | `discover/ct.py::CertStreamClient` | 聚合 WebSocket，延迟更低；公共实例常断流，只作补强，断线自动退避重连 |
| 域名排列 | `discover/dnsprobe.py` | 从词库派生词根，单词 + `机构词×主题词` 组合，批量解析 |

CT 条目解析的两个坑（都会导致静默丢证书，所以写进注释并有测试守着）：

- `x509_entry`（type=0）：证书长度在 `leaf_input[12:15]`
- `precert_entry`（type=1）：得从 `extra_data` 的证书链里取，长度在 `[3:6]`

### 2.2 词库：363 词根 / 6 语义簇 / 拼音自动派生

`discover/keywords.py` 里按语义簇组织，而不是一锅乱炖：

| 簇 | 词根数 | 例子 | 权重策略 |
| --- | --- | --- | --- |
| `authority` | 65 | 国科、中科、社科院、发改委、民政部、卫健委、乡村振兴局、老龄委 | 强簇，直接加权 |
| `policy_theme` | 119 | 养老、康养、银发、社保、医保、低保、高龄补贴、共同富裕 | 无强簇支撑时 ×0.30 |
| `scam_signature` | 50 | 民族资产解冻、云数贸、1040工程、资金盘、解冻费、对碰奖 | 强簇，直接加权 |
| `carrier` | 56 | APP、平台、公众号、工作站、服务中心、专员、主任 | 无强簇支撑时 ×0.70 |
| `brand` | 35 | kuaishou、douyin、unionpay、icbc、psbc、chinamobile | 强簇 |
| `inducement` | 38 | 免费领、领鸡蛋、米面油、到场即送、签到领、现金红包 | 有强簇 ×1.0，否则 ×0.55 |

关键实现：用 `pypinyin.lazy_pinyin` 把中文词自动转成拼音（`国惠 → guohui`、`中科 → zhongke`），
再把所有变体编译成**一条** alternation 正则，一次扫描完成全部匹配：

```python
self._pinyin_re = re.compile("|".join(re.escape(t.pinyin) for t in self._by_pinyin), re.IGNORECASE)
```

替代了原来「逐词循环 `in` 判断」的写法。实测 **5 万个域名/秒**（单核），匹配不再是瓶颈。

### 2.3 放宽准入，把降噪挪到后面

原则改成「宁可错杀一万」：

- 命中 1 个词根就入库，`tier=candidate`，并记录 `discovery_reason`（命中哪些词、来自哪条通路）
- 之后由 `triage.py` 按证据分级；确认无害的降到 `cold` 或人工 `dismissed`，**记录不删**
- 冷存保留 180 天，新证据可以复活

降噪放在三道闸上，而不是准入线上：

1. 白名单极窄，且**防伪造后缀**（`gov.cn.evil.top` 不放行，有测试）
2. 语义簇降权（见上表）
3. ICP 备案只查 `candidate` 以上，令牌桶 10 次/分钟，30 天缓存；查不到记 `unknown` 而非 `unregistered`

## 三、分级与研判分离

新增 `triage.py`。**分级（tier）不是评分（verdict）**：评分回答「有多像」，分级回答「我们现在拿它怎么办」。

| 档位 | 进入条件 |
| --- | --- |
| `candidate` | 词库命中 / 分数 ≥12 / 发现层直投 |
| `watch` | 分数 ≥50，或 ≥32 且有紧迫性（域名 ≤30 天、强制下载、非商店分发、情报源命中） |
| `confirmed` | 人工复核或官方清单（`SILVER_CONFIRM_REQUIRES_OFFICIAL`） |
| `cold` | 分数 <0.30 且无强证据 |
| `dismissed` | 人工排除，必须填理由 |

两条规则保证名单不会失控：

- **首次分级可自由落档，之后只允许升级**（已确认的不降级）
- **衰减**：长期无新证据逐级下移，不让「三年前的候选」永远占着待办

分级结果会回写 `Asset.tier`，控制台与 `list` 命令都按它筛。

## 四、图谱归因

`graph/` 四个文件：`schema`（节点关系定义）、`store`（内置 SQLite / Neo4j 双后端）、`build`（从资产装配）、`community`（社区发现）。

20 类节点、17 种关系。边权按「伪造难度」定，因为归因的可信度取决于证据有多难被换掉：

| 关系 | 权重 | 理由 |
| --- | --- | --- |
| `SHARES_CERT` | 0.90 | 换证书要重新签名 |
| `USES_WALLET` | 0.85 | 资金链换不掉 |
| `ICP_ENTITY` | 0.70 | 实名信息，但可买壳 |
| `SAME_TEMPLATE` | 0.65 | 换皮即变，但批量作业常用同一套 |
| `RESOLVES_TO` | 0.35 | 共用 CDN 会把半个互联网连成一团，弱边且限定方向 |

三个实现决定：

1. **`RESOLVES_TO` 只在 `url/domain → domain` 方向计入聚类**。反方向会把同一 CDN 上的所有站点连成一个巨型团伙。
2. **节点 ≤50 走连通分量，否则 Louvain**。小图上 Louvain 会把一个明确的簇切成几块。
3. **单点不成团**：社区里可疑资产 <2 且无已确认资产时不建团伙。名单虚胖比漏报更难用。

团伙摘要写「凭什么连起来」，而不是「疑似诈骗」：

```
含 9 个关联节点（apk 2、url 1）；2 处互相内嵌，2 处同页面模板，2 处同一证书签名；其中 2 项高度可疑
```

## 五、证据不再依赖数据库

三层：

| 层 | 文件 | 机制 |
| --- | --- | --- |
| 事件日志 | `core/eventlog.py` | 只追加 JSONL；每条带 `seq`、`prev_hash`、内容哈希；1 秒/256 条 group commit fsync；`flock` 跨进程 |
| 证据文件 | `settings.evidence_dir` | sha256 内容寻址，落盘即校验 |
| 异地副本 | `core/replica.py` | 增量分片 `part-00000001.jsonl`，写完回读比对大小；后端 dir/S3/WebDAV |

`log verify --deep` 三段校验（序号连续、前序哈希衔接、内容哈希），能指出断在第几行、为什么断：

```
事件日志异常：第 500 行，序号断裂：期望 500 实际 501
```

SQLite 这边保留 `synchronous=NORMAL`：一条不丢由事件日志的 fsync 兜底，没必要让每次 `UPDATE` 都等磁盘。

## 六、沙箱

`sandbox/web.py` 用 Playwright 真跑页面，`sandbox/apk.py` 做权限→行为推演。边界写死在代码里：

- 解析目标域名，命中私有网段直接拒（SSRF）
- 路由层 abort 所有非 GET/HEAD 请求——观察者不替对方提交表单
- 每次新 context，`accept_downloads=False`
- APK 三级降级 MobSF → adb/emulator → 静态推演，降级时标 `static-inference`，**绝不冒充动态结果**

`apk.py` 里有 20 条权限→行为映射和三组致命组合（短信+通讯录、悬浮窗+无障碍、推装+枚举应用），
以及反检测特征（`SECURITY_PACKAGE_HINTS`）——这些是「装成安全软件来躲查杀」的常见手法。

## 七、接口与前端

新增（`api_extra.py`）：

| 分类 | 端点 |
| --- | --- |
| 发现 | `/api/discover/status|events|inject|search|keywords` |
| 图谱 | `/api/graph/stats|overview|node|rebuild|communities`、`/api/campaigns/{id}/graph` |
| 资产 | `/api/assets/{id}/enrich|probe|tier|graph` |
| 运维 | `/api/ops/status|tasks|events|verify|cycle|replica|communities` |
| 监控 | `/api/metrics`（Prometheus 文本）、`/api/stream`（SSE） |

用 SSE 而不是 WebSocket：单向上报足够，浏览器原生 `EventSource`，穿反向代理更稳。

前端新增三页（`web/static/views.js`，无构建步骤）：发现流、关系图谱（canvas 力导向）、运维。
图谱的标签只在缩放足够/悬停/团伙页时显示，钱包与证书做缩写——否则 20 个节点的标签会糊成一团。

## 八、依赖与部署

`pyproject.toml` 补齐真实依赖：`cryptography`、`dnspython`、`pypinyin`、`networkx`、`pydantic`。
可选依赖分组：`sandbox`（playwright）、`stream`（websockets）、`s3`（boto3）、`neo4j`、`full`。

`docker-compose.yml` 用 profile 编排：`graph`（Neo4j）、`replica`（MinIO + 自动建桶）、`sandbox`（MobSF）。
缺省时不启这些服务，系统自动降级并在运维页如实标注。

容器仍是只读根文件系统 + `no-new-privileges`，只有数据卷、`/tmp`、`~/.cache` 可写。

## 十、已知取舍

- **扫描范围**：不做全端口扫描、不无差别爬全网。低效，且会被运营商盯上。
- **ICP 判定**：没有稳定公开 API，未配置时按 `unknown`，不参与评分。
- **沙箱 ≠ 真机**：桌面 Chromium 与移动 WebView 行为有差异；APK 动态分析依赖 MobSF 或真机。
- **不提供可直接点击的诈骗网址清单**：会过期，也会被二次传播利用。
