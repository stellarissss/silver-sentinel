# 词库识别机制重构：调研、诊断与方案

> 版本：调研稿（未实施）　日期：2026-11-08
> 结论先行：**问题不在词表不够严谨，而在建模对象选错了。现在的词库建模的是「涉老行业的词汇」，不是「欺诈行为」。**
> 同一批词在正规垂类站的出现率与诈骗站一样高，所以再怎么调权重，排序也只能是随机的。

---

## 一、结论先行

用现网同一份词库（917 词条 / 18 簇），对 25 个**正规**中文站点与 1 条**已知诈骗话术**做同口径打分：

| 站点 | 性质 | 词库分 |
|---|---|---|
| jiankang.cctv.com | 央视网健康频道 | **0.990** |
| www.39.net | 39 健康网 | **0.990** |
| health.people.cn | 人民网健康 | **0.990** |
| tuiyijunren.cn | 退役军人网（用户指出） | **0.988** |
| www.yanglaocn.com | 中国养老网（行业门户） | **0.983** |
| www.chealth.org.cn | 中国健康促进基金会 | **0.979** |
| supplier.alibaba.com | 阿里巴巴国际站 | **0.975** |
| www.chuhai-club.com | 出海club（B2B 资讯） | **0.974** |
| —— | **已知诈骗话术样本** | **0.990** |
| www.53kf.com | 客服 SaaS（用户指出） | 0.513 |
| www.yige-tech.com | 外贸营销服务商（用户指出） | 0.209 |

- 25 个正规站中，**8 个（32%）得分 ≥0.97**，与诈骗样本持平甚至更高；**14 个（56%）≥0.5**。
- 列表页按 `Asset.score desc` 排序（`api.py:470`、`api_extra.py:178`），所以这些站必然排在最前面。**用户看到的"排行榜"是词库分的直接投影，不是判断失误，是机制使然。**
- 一个典型细节：央视健康的文章标题《入秋关节僵硬 教你这样"解冻"》，命中 `scam_signature` 的「解冻」，触发"强簇一票放行"，把其余折扣全部解除 → 0.99。

**这不是调参能修的。** 只要「养老/补贴/退役/健康/平台」这类词还在计分，正规垂类站就会永远压过真正的诈骗站——因为正规站的字数更多、内容更丰富、这些词出现得更密。

## 二、实测：三个样本到底命中了什么

### 2.1 www.53kf.com（客服 SaaS，0.513）

15 条命中，**全部来自导航栏、产品介绍、页脚**，没有一个来自"承诺"或"指令"：

| 词 | 簇 | 来源语境 |
|---|---|---|
| 客服 / 系统 / 网站 / 中心 / 工单 / 应用 / 认证 / 公众号 / 小程序 | carrier | 产品名称、功能列表 |
| 充值 | payment | "充值中心"（指给 SaaS 账户充值） |
| 转化 / 话术 | sales_jargon | "营销转化更好"、"发送针对性话术"（产品功能） |
| 私域 / 微信群 | channel | "微信工具，私域运营"（产品功能） |
| 高新技术 | policy_theme | "国家高新技术企业"（资质） |

### 2.2 tuiyijunren.cn（退役军人网，0.468）

**域名单独命中 0.468，正文零贡献。** `tuiyijunren` → 拼音切分为「退役军人」→ `authority` 簇 → 因为 `authority` 属于"强簇"，不享受任何折扣。

这里暴露的是分类学错误：**「退役军人」既是机构名的一部分（退役军人事务部），也是人群称谓（退役军人群体）**。前者被冒用才是信号，后者是任何涉军服务站的必备词。同一个词，两种角色，共用一个权重。

### 2.3 www.yige-tech.com（外贸营销，0.209）

只命中 `carrier`（平台/网站/系统/官网/中心/应用/上市）、`sales_jargon`（转化）、`collectible`（"目标市场**评估**"）。分数不高，但它仍然进了候选池——因为 `discover_hint ≥ 0.3` 或者其它结构信号。**噪音不一定要高分才能造成伤害，它只需要排在真目标前面。**

### 2.4 正规垂类站（0.97+ 的那批）

yanglaocn.com 命中的是：养老/老年/养老院/养老金/居家养老/老龄/老年大学/社保/退休/敬老院/养老保险/公积金/养老社区/安养/医养/颐养/社会福利中心/民政部/民政局/老龄办/主任/局长……

**这些词，恰恰是"中国养老网"这个网站的行业术语表。** 用它来判定"涉老诈骗"，等于用「医学词汇」判定「非法行医」。

### 2.5 为什么你看到的几乎全是正常站

你提到"真正的诈骗网站只有极少部分，而且没有 APK"——这一点本身就是系统性的，不是偶然：

1. **最硬的三个结构信号在长尾里天然稀少。** 强制装包、非应用商店分发、未备案+域名极新，这三条只在骗局的**最后一步**出现。而发现层（CT 证书流）捞到的大多是**刚注册、还没建站或刚建站**的域名，此时页面还在做引流，APK 还没上线。
2. **黑产大量使用已备案壳站。** 一旦有备案，`DIST-002`（16 分）就没了，且 `decide()` 里"已备案降为候选"会再压一档。
3. **发现层是"广度优先"的**，它按命名意图捞域名（含养老/补贴/退役/惠民），而命名意图和诈骗意图的相关性，远低于直觉。

于是链条变成：**结构信号普遍缺失 → 排序几乎完全由词库分决定 → 词库的缺陷被 100% 放大到排行榜上。**

换句话说：不是"排序把客服站排到了第一"，而是**除了词库分，现在没有第二个信号在真正参与排序**。修词库是必要的，但只修词库不够——必须补上"不依赖词汇"的判据（见第六节的主体一致性）。

## 三、根因解剖

按影响从大到小，每条都对应到具体代码。

### R1　建模对象错了：词库描述"行业"，不描述"欺诈"

`CLUSTERS` 的 18 个簇里，`policy_theme`(159)、`health_product`(99)、`authority`(87)、`carrier`(56)、`elder_care`(48) 这 5 个簇共 449 词（占 49%）全是**行业词汇**，正规矩内人天天用。只有 `scam_signature`(61) 和 `variant`(22) 勉强算"黑话"，而黑话是会被规避的——骗子改一个字，词表就失效。

> 词表越全 → 正规站命中越多 → 排序越差。**这是一个负向的规模效应。** 可核对的事实：v1.0（`6cfa523`）词库约 442 条唯一词条，现在库内去重 845 条，**几乎翻倍，而扩得最猛的一次是 v1.5** ——正是误报开始需要靠"个案护栏"来压制的时点。

### R2　没有背景基率（IDF）

`carrier` 的「平台/系统/中心/网站/官网/客服」在中文网页的文档频率 >80%，`policy_theme` 的「养老/健康/补贴」在垂类站接近 100%。但它们在 `_finalize()` 里按 `0.32 / 0.55` 这种"可疑度"计权，**从未用"正常语料里有多常见"做过折减**。

结果：`carrier` 在现代网页里是纯噪声，却稳定贡献 0.09～0.10 的正分；`policy_theme` 贡献 0.16。这两个加起来已经 0.25，接近落库门槛 0.30。

### R3　noisy-OR 让弱信号可以无限堆叠

`_finalize()` 的注释写着"避免十条弱特征超过一条铁证"，但实际计算是：

```
score = 1 - Π(1 - w_i)      # w_i 已乘折扣
```

5 个 0.09 的弱信号 → `1 - 0.91^5 = 0.376`；8 个 → 0.53。**弱信号越多，分越高，而弱信号的数量取决于页面有多"内容丰富"，不取决于有多"可疑"。** 这正是 53kf（0.513）和 yanglaocn（0.983）的差别来源——后者是个大门户，词自然更多。

### R4　"强簇一票放行"是个放大器，不是过滤器

```python
strong = {"scam_signature", "authority", "brand"}
has_strong = bool(strong & set(best))
...
weight = 1.0 if has_strong else 0.30   # 其余所有簇
```

只要命中一个 `authority`（87 个词里任意一个：民政局、老龄办、红十字会、供销社……），**其余所有簇的 0.30 折扣全部消失**，policy_theme 从 0.165 直接跳到 0.55。

央视健康命中「解冻」触发强簇 → 其余全价 → 0.99。yanglaocn 命中「民政部」→ 其余全价 → 0.983。**这一条是 0.97+ 误报的直接生成器。**

### R5　authority 混淆了"被报道的对象"与"被冒用的名义"

「民政部」出现在三类页面里：
1. 新闻：「民政部发布通知」——被报道对象，**正常**
2. 行业门户：「民政部政策解读」——引用来源，**正常**
3. 诈骗站：「民政部指定申领入口」——**被冒用**

现在的词库只判断"出现了"，不判断"以什么身份出现"。这三类页面在词库眼里完全一样。

### R6　域名拼音被当成强证据

`match_domain` 的拼音通道做得其实很讲究（音节切分 + 边界对齐，挡住了 Snowflake 随机串和德语人名），但**语义上不成立**：域名里有「养老/退役军人/扶贫」只说明**命名意图属于这个领域**，不说明**站点在骗人**。

垂类门户、地方信息网、行业协会、老年大学、甚至正规养老院，都会这么起名。`tuiyijunren.cn` 0.468 全部来自域名，正文一个字没贡献。

### R7　一个标量承担两个职责

`score` 同时用于：
- **排序**：决定取证队列的优先级（要宽，宁滥勿缺）
- **定罪**：决定 tier=watch / 生成报告（要严，宁可漏）

上次把 `policy_theme` 折算从 0.30 提到 0.55（v1.8），就是为了救"扶贫/养老域名过不了 0.30 落库门槛"的召回——代价是 yanglaocn 这类站直接进 0.98。**这不是参数没调好，是一个变量扛了两件事，必然互相拉扯。**

### 附带发现：解码会把中文站判成"零命中"

实验中发现 `requests` 的 `apparent_encoding` 把 53kf 误判成 `Windows-1254`，解码后中文全乱，命中数从 15 掉到 0。项目里 `collectors/http.py:150` 直接用 `resp.text`，若响应头缺 charset 且库猜错，正文会变成乱码——**表现为"这站没任何特征"，实际是解码失败**。这条与词库无关，但会静默吃掉召回，建议单独修。

## 四、外部调研：有什么可以复用

结论先说：**中文"涉老诈骗网站"这个细分领域，没有可直接下载的模型或数据集。** 但工具链是齐的，缺的是标注数据和判据设计。

### 4.1 可直接借鉴的

| 项目 | 是什么 | 我们能用的部分 | 局限 |
|---|---|---|---|
| [ChiFraud](https://github.com/xuemingxxx/ChiFraud)（COLING 2025） | 中文网络文本欺诈检测数据集，10 类（正常/赌博/招嫖/假证/假卡/违禁药/套现/假认证/假SIM/地下贷） | **标注规范与类别体系**；baseline 代码（BERT/ChineseBERT/fastText/Qwen 全套对比脚本） | 类别是"黑产交易"，不含"涉老诈骗"；文本是短句不是网页 |
| [ChiPhish](https://github.com/joanyy/ChiPhish)（Computers & Security 2025） | 中文钓鱼网站检测；实测 72 个业界检测器 + 10 个 ML 检测器，**跨区域检测率有时低于 1%**；自建中文特征集后做到 0.98 DR @ 0.01 FPR | **中文特有特征工程清单**（备案号、客服 QQ、支付方式、页面认证标识）；"西方模型在中文站上几乎全瞎"的实证 | 任务是"仿冒登录页"，不是"话术诈骗"；数据集在 Zenodo 需申请 |
| [SetFit](https://github.com/huggingface/setfit) | 少样本文本分类；8 条/类即可接近全量微调 RoBERTa-large | **标注成本能压到 120～300 条**；CPU 几分钟训练完；分类头是逻辑回归，可解释 | 依赖 sentence-transformers |
| [fastembed](https://github.com/qdrant/fastembed) + `BAAI/bge-small-zh-v1.5` | ONNX 运行时跑中文 embedding，**90MB / 512 维 / 纯 CPU** | 社区实测：暖态单条 **~9ms**，批量 **~2.5ms/条**；2C2G 可跑 | 单靠 embedding 排序不够（实测"只能粗筛"），必须与关键词联合 |
| Qwen3-0.6B（LoRA） | 0.6B 通用小模型，可做结构化输出 | 若要"输出 JSON + 引用原文"，比 SetFit 更灵活；F1 与 BERT 差距 <0.5pt | 推理慢一个量级（13 RPS vs 60 RPS），且要 PyTorch（~800MB 依赖） |
| [content-compliance-checker](https://github.com/mengbao/content-compliance-checker) | 广告法/医疗功效/金融承诺词检测 | **"上下文感知"的做法**：命中后检查否定语境（"第一次使用"不报"第一"、"治愈系音乐"不报"治愈"）——正是我们缺的那一层 | 面向营销合规，规则简单 |
| [trafilatura](https://github.com/adbar/trafilatura) | 网页正文抽取（去导航/页脚/推荐位） | **53kf 的 15 条命中里绝大多数来自标题、导航、产品功能列表与资质栏**，没有一条来自"承诺"或"指令"；抽正文能砍掉大部分这类噪声 | 中文效果需实测 |

### 4.2 看过但不建议引入的

- `wfh45678/radar`（1.6k★，中文风控规则引擎）：我们已有规则引擎 + YAML DSL，引入只是换语法。
- `Phishpedia` / `PhishIntention`（视觉 logo 识别）：能判"冒充了哪家机构"，但要目标检测模型 + GPU，成本远超收益。**可以用更便宜的方式替代：页面自称主体 vs 备案主体的一致性比对。**
- 各类 "scam website dataset" 小仓库（0～5★）：无标注规范、无出处，不可用。

### 4.3 需要自己建的（绕不开）

1. **评测集**：现在完全没有。`tests/test_keywords_precision.py` 和 `test_false_positive_guard.py` 都是**个案钉子**——每踩一个坑钉一颗。这解释了为什么词表从 442 条涨到 845 条却越来越差：**只有局部补丁，没有全局指标。**
2. **正样本**：官方通报（公安部/各地反诈中心/12377 涉养老诈骗专区）+ 已确认案件 + 人工复核。可爬、可增量。
3. **负样本**：现有的 `dismissed` 档就是天然负样本池，现在只用来"防止重复收"，**没有回流到学习/校准**。

## 五、方案空间：四条路线

### 路线 A：词库治理（低成本，必要但不充分）

1. **角色拆分**：把词从"簇"改成"角色"
   - `entity`（机构名：民政部、老龄办）—— 只在"申领/指定/授权"句式里才算
   - `audience`（人群：退役军人、老知青、军属）—— **不计分，只做路由**
   - `domain_word`（行业词：养老、补贴、康养）—— **不计分，只做路由**
   - `action`（行为：领取、登记、扫码、转账、下载）
   - `promise`（承诺：国家发放、保本保息、包治百病）
   - `block`（阻断核验：保密、别告诉子女、仅限今天、应用商店搜不到）

2. **计分只认组合**：`promise × action`、`entity × action`、`block × (promise|action)`。单个 `domain_word` 永不计分。

3. **引入背景基率**：用 500～1000 个正常网页统计每个词的文档频率 df，`weight ∝ -log(df)`。carrier 类会自然归零。

4. **域名命中降级为 hint**：只影响"要不要抓"，不影响"有多可疑"。

- 成本：3 天（含重构 + 回归）
- 预期：上述 8 个 ≥0.97 的误报基本清零；召回不受影响（真诈骗站的"承诺+指令"结构还在）
- 风险：低。可灰度（新旧并存，只改排序）

### 路线 B：结构化抽取 + 结构判据（中成本，最高可解释）

判据从"词"变成"言语行为三元组"：

```
promise:  (承诺内容, 对象, 金额/期限, 是否越界)
action:   (要求动作, 渠道, 门槛, 是否不可逆)
block:    (阻断话术, 阻断对象)
```

**判据：`越界承诺` 与 `不可逆指令` 同现 ≥2 类，且 `主体不可核验`，才是诈骗。**

这套判据的好处：换词不掉分。"每日返利 1%"→"日化收益 1%"，词表失效，但"固定收益承诺"这个语义槽位还在。

- 成本：4～5 天（正则 + 依存/LLM 抽取两种实现）
- 风险：抽取质量依赖正文质量；需要正文抽取先行

### 路线 C：话术原型语义匹配（中成本，无需大量标注）

用 `bge-small-zh-v1.5`（90MB ONNX）把页面切片，与 40～60 条**话术原型**做 max-sim：

```
"凭身份证登记即可领取国家补贴，名额有限"
"加入会员每日返利，拉人再拿直推奖"
"这个药能根治糖尿病，医院不会告诉你"
"应用商店搜不到，请关闭安全检测后安装"
```

- 命中即"这个页面在讲这套剧本"，**且能展示命中的原型句**（可解释）
- 成本：2～3 天；内存 +300MB；单页 20 个切片 × 9ms ≈ 0.2s
- 风险：原型覆盖不到的剧本会漏；必须与关键词联合（ChiFraud/社区实测都表明 embedding 单独只能粗筛）

### 路线 D：小模型分类（中高成本，需标注）

SetFit + bge-small-zh，三类（scam / benign / unsure），**120～300 条标注即可训**，CPU 几分钟。

- 产出：一个 30MB 的分类头 + 一句置信度
- 关键：**训练集必须包含"正规垂类站"作为 hard negative**（yanglaocn、39.net、养老门户、退役军人服务网），否则模型学到的还是"行业 vs 非行业"
- 成本：标注 120 条约 4 小时（2 分钟/条）；训练 + 集成 2 天
- 风险：标注规范不统一会导致模型学到标注者的偏见；需要双人交叉 20%

### 路线 E：LLM 复核（已有能力，改用法）

现有 `analyzers/llm.py` 已经能输出 `classification + reasoning + cited_evidence`，但只在灰区抽样、且按 token 计费。

改法：**先由 A/B/C 筛到 top-50，再让 LLM 只判这 50 条**。成本从"每页都判"降到"每天 50 次"。并且加一道**引文逐字回验**：模型声称引用的 `[E:编号]` 片段必须在原文中真实存在，否则该结论作废——这是防幻觉的硬约束，现有代码只校验格式，没校验内容。

## 六、推荐架构：两段式 + 三个机制

```
                    ┌─────────────────────────────────────┐
  发现（CT/DNS） →  │  召回段：宽。只回答"值不值得抓"        │
                    │  词库（角色化）+ 域名 hint + 证书关联  │
                    └──────────────┬──────────────────────┘
                                   ↓ 取证（抓页面 + 抽正文）
                    ┌─────────────────────────────────────┐
                    │  判据段：严。只回答"是不是诈骗"        │
                    │  ① 结构判据（承诺/指令/阻断 同现）    │
                    │  ② 原型语义（命中哪套剧本）           │
                    │  ③ 小模型（scam/benign/unsure）      │
                    │  三者投票：≥2 一致 → watch            │
                    └──────────────┬──────────────────────┘
                                   ↓
                    ┌─────────────────────────────────────┐
                    │  排序段：按"可核查证据条数"排          │
                    │  官方通报 > 共用收款/证书 > 引文 > 评分 │
                    └─────────────────────────────────────┘
```

**三个必须同时做的机制：**

1. **主体一致性（entity resolution）**
   页面自称是谁（"我们是XX部指定平台"）vs 备案主体是谁 vs 域名注册人是谁。
   三者不一致 = 冒充的直接证据，且**不依赖任何词表**。
   项目已有 ICP 查询，只差一次比对。这是投入产出比最高的一条。

2. **排序与定罪分离**
   - `priority`（排序）：宽口径，用于取证排队
   - `verdict`（定罪）：严口径，只在判据段产生
   - 现在 `api.py` 按 `score` 排序，改为按 `priority` 排序，`score` 只作为展示项

3. **负样本闭环**
   `dismissed` 的资产自动进负样本池，每周重跑评测集。没有这一步，任何模型都会随时间漂移。

## 七、落地路径（建议分三步，每步有验收）

### 第一步：止血 + 建尺子（3～4 天，零新依赖）

- 建 `eval/seed.jsonl`：**正 40 / 负 80**（负样本必须含正规垂类站：养老门户、健康门户、退役军人服务网、B2B 外贸站）
- `silver-sentinel eval` 命令：输出 precision@50、recall@500、AUC，作为后续一切改动的唯一裁判
- 词库角色化 + 组合计分 + 域名降级
- 正文抽取（先试 trafilatura，中文不行就退回 playwright 的 `main/article` 选择器）

**验收：** 25 个正规站的词库分全部 <0.35；40 条正样本 recall 不低于现在。

### 第二步：结构判据 + 原型（4～5 天）

- 承诺/指令/阻断三类槽位的正则 + 关键词共现
- 40～60 条话术原型 + bge-small-zh ONNX
- 三源投票，≥2 一致才 watch

**验收：** precision@50 从当前基线提升到 ≥0.6；换词变体（谐音/拆字/英文混写）召回不下降。

### 第三步：小模型 + LLM 复核（取决于标注预算，1 周）

- SetFit 三分类，120～300 条标注
- LLM 只判 top-50，引文逐字回验
- dismissed 回流

**验收：** 连续 7 天 watch 列表人工抽查准确率 ≥0.7。

## 九、附录：本次实验如何复现

```bash
# 1. 取页面（务必强制 utf-8，apparent_encoding 会误判）
curl -sSL -A "$UA" https://www.yanglaocn.com/ -o page.html

# 2. 抽文本 + 用现网词库打分
python3 - <<'PY'
import re, sys; sys.path.insert(0,"src")
from bs4 import BeautifulSoup
from silver_sentinel.discover.keywords import get_library
html = open("page.html", encoding="utf-8", errors="ignore").read()
s = BeautifulSoup(html, "html.parser")
for t in s(["script","style"]): t.decompose()
txt = re.sub(r"\s+", " ", s.get_text(" "))
m = get_library().match_any("www.yanglaocn.com", txt[:4000])
print(round(m.score, 3), [(h.term, h.cluster) for h in m.hits])
PY
```

样本清单（25 个正规站）：央视健康、人民健康、39 健康网、中国健康促进基金会、中国养老网、退役军人网、阿里巴巴国际站、出海club、头条、安阳信息港、网易健康、网易外贸、西瓜 web、53kf、yige-tech、中国研究生招生信息网、以及 8 个无关站（游戏/翻译/视频，作为"词库不该起火"的对照组）。

**样本量说明：** 25 个站 + 1 条诈骗样本，不足以给出精确 FPR，但足以证明"排序失效"这个方向性结论——8/25 的正规站得分高于已知诈骗样本，已经超出任何可接受的误报水平。
