## 二、六个真问题（按修复价值排序）

### 问题 1：词库的子串匹配制造了 78% 的假目标

旧实现把域名所有 label 拼成一个字符串做子串匹配，于是：

| 现象 | 数量 | 根因 |
| --- | --- | --- |
| Snowflake 随机主机名 | 700+ | `-mz11195` / `-gk68102` 被切成 `mz`（民族）、`gk`（国科） |
| 含 `people` 的外国站 | 736 次命中 | `people` 在品牌簇里，`oceanpeople` / `purepeople` 全中 |
| 德语人名 | 若干 | `minge`（名额）出现在 `nadinejasmingeissbuehler` 里 |
| `-fp30388` 之类 | 若干 | 拼音缩写 `fp`（扶贫）撞上随机后缀 |

这不是「宁可错杀」的合理成本——错杀的前提是**成本可控**。实际后果是
富化队列被垃圾占满：22 小时只做完 1,354 个资产的评估，剩 1,159 个连证据都没有。

**已修**（`discover/keywords.py`）：

1. 缩写只在整段 label 等于缩写（或缩写 + ≤3 位数字）时成立；
2. 英文词只认整段 label，不做子串；
3. 拼音匹配前先做**音节切分**（用 pypinyin 的 426 个音节做 DP），命中必须落在音节边界上；
4. 多段域名拼回去再匹配一次，`yanglao-jijin.xyz` 仍能命中「养老基金」。

回放 2,512 个存量域名：**命中数从 2,512 降到 543**，被淘汰的样本全部是随机主机名、
外国人名、无关英文站；真目标（国惠、老龄委、公积金、解冻、抖音仿冒）一个没掉。

### 问题 2：一半资产是同一个站的不同主机

2,512 个主机只对应 **1,251 个注册域**；311 个注册域贡献了 1,572 个主机
（`wechat-art.xyz` 一个站 35 个、`snowflake.app` 362 个）。
每个主机都要独立做 DNS、RDAP、备案，配额被放大了 2 倍，图谱也被撑成一团。

**已修**：CT 落库时归并到注册域，主机清单进 `meta.hosts`；免费二级域平台
（duckdns / dpdns / ngrok…）不归并——骗子的站就建在这些平台的子域上，归并就等于丢线索。
无法识别的国别后缀宁可不归并，避免把两个无关主体焊成一个。

### 问题 3：证书指纹被丢掉，最强的同源证据没了

`discovery_events.raw` 里有完整的 `fingerprint`，但 `assets.fingerprint` 全是空
（0 / 2,513）。后果是图谱只能连 DNS——而 DNS 是最容易变的弱关系。
`wechat-art.xyz` 那 35 个子域明明是同一张证书签的，图上却连不起来。

**已修**：CT 落库写 `asset.fingerprint`，图构建优先读这一列建 `HAS_CERT` 边。

### 问题 4：ICP 一次都没查（0 条）

全部资产 `icp_status=unknown`，`DIST-002`（无备案）规则从未触发。
这才是「研判停在证据不足」的主因——缺了「是否境内备案、备案主体是谁」这一维，
剩下全是弱信号。

**已解决**：本机部署 `ICP_Query`（Docker，`yiminger/ymicp`），并修了客户端三个问题：

1. `_iter_records` 不认识 `params.list` 这种嵌套 → 真实接口返回永远解析成「空」；
2. 接口报错（`code=500` / `success=false`）被当成「未备案」→ 会批量制造假结论；
3. 新增工信部**违法违规名单**查询（`/query/bweb`），比「有没有备案」更硬。

实测：`baidu.com` → `京ICP证030173号 / 北京百度网讯科技有限公司`；
`qq.com` → `粤B2-20090059 / 深圳市腾讯计算机系统有限公司`；
5 个诈骗域名全部返回 `unregistered`。

### 问题 5：动态取证是空的

沙箱代码写得很细（禁内网、只读不写、蜜罐探针），但**一次都没执行过**：
服务器上没有 Chromium，且没有隔离出口——OPSEC 直接 fail-closed。
所以 22 小时的证据只有「评分快照」，没有一个页面原文、没有一张截图。

**已解决（能力）**：服务器装了 Playwright + Chromium（含系统依赖），
`probe_web` 现在一次落四份证据：正文、HTML 原文、首屏截图、运行时网络请求。
用本地假页面做了端到端验证（JS 延迟 1.2 秒才吐真内容 + JS 拼下载链接），
四份证据全部拿到，截图里能看到被 cloaking 藏起来的「国家惠民养老补贴申领中心」。

**仍缺（出口）**：没有代理时仍拒绝运行。这一条必须靠一个境外 SOCKS5 出口解决。

### 问题 6：吞吐口径骗了自己

运维页显示的 `1.7/分` 其实是「资产入池速度」，不是采集速度；真实采集是 1,185 张/分钟。
已拆成 `certs_per_min` 和 `assets_per_min` 两个字段。

## 五、结论

**系统能发现问题，但精度不足以支撑长期运行**：22 小时产出的 2,513 个资产里，
大约 400 个值得看，其余是匹配算法的副产品。这一轮把「发现」从「能命中」推到
「命中即可信」，同时把 ICP 与动态取证两条腿接上了——后者还差一个出口。

真正的拐点在备案：一个域名查不到备案、却挂着「国惠养老」的牌子，这本身就是可举报的事实；
反之查到了备案主体，就能从「可疑域名」升级到「可追责主体」。这也是下一轮的主线。
