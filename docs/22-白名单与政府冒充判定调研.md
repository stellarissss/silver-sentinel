# 白名单、政府冒充判定与备案失效复盘

> 本轮只做调查与验证，未改代码。所有结论都来自本地实测：32 个负样本、6 个正样本、
> 13,508 条政府网站记录、1,451 家稿源单位、10,000 条新闻域名。

## 0. 结论先行

1. **备案没起效果，首要原因不是算法，是服务没在跑**。`SILVER_ICP_API` 默认为空，
   `install.sh` 从不部署 `ICP_Query`，`doctor` 也不检查这一项。配过、实测过、后来悄悄失效，
   没有任何一处会报警。
2. **更关键的是查错了对象**。诈骗站伪造备案号（实测两个不同域名写同一个号，
   页面 JS 用 `Math.random()` 现生成），查「这个域名有没有备案」永远只能得到"没有"，
   和"没备案"完全无法区分。要查的是「**这个备案号属于谁**」。
3. **你的白名单思路成立，但白名单不能当过滤器**。53kf、易歌科技、39 健康都不在任何
   政府/媒体白名单里——按"不在白名单就排除"会把整个中文互联网判成诈骗。
   白名单的正确角色是**验证"自称"**：它说自己是谁，去权威库里查那个"谁"的官方域名是不是它。
4. **"声称政府"这个判据实测很干净**：32 个负样本 **0 误报**，5 个活的正样本命中 3 个。
   但抽取位置必须严格——只认**页头**和**版权/主办声明行**，且**必须剔除链接**。
   红十字会被页脚友情链接误伤这件事，我第一次就踩到了。
5. **有一条零误判的硬判据**：`政府网站标识码：bm01000001`。这是中国政府网自己的码，
   出现在 `np4w53.cn` 和 `hksm38.com.cn` 上。政府网站标识码只发给 `.gov.cn`，
   非政府域出现即伪造，不需要任何模型。

## 1. 为什么查备案没起效果

分四层，从外到内，每层都有代码位置。

### 1.1 第一层：服务不在

```python
# config.py:115
icp_api_base: str = ""          # 默认空
# config.py:451
def icp_ready(self) -> bool:
    return bool(self.icp_enabled and self.icp_api_base)
```

```python
# enrich/icp.py:275
if not settings.icp_ready:
    return ICPResult(domain=domain, status="unknown", error="备案查询未配置…")
```

`install.sh` 全文搜不到 `ICP_Query` / `ymicp`。`docs/12` 里的部署方式是**手工**：

```bash
docker run -d --name ymicp --restart unless-stopped -p 127.0.0.1:16181:16181 yiminger/ymicp
```

服务器重装、容器被清、`docker prune`，这个服务就没了。而 `doctor` 只看心跳和取证队列：

```python
# cli.py cmd_doctor：只有 heartbeat + capture_queue_health + discover
```

**结论**：ICP 是唯一一个"挂了完全静默"的外部依赖。

### 1.2 第二层：只查 candidate 以上

```python
# config.py:127
icp_tiers: str = "candidate,watch,confirmed"
```

而发现侧进来的资产绝大多数落在 `cold`。也就是说，即使服务活着，
**95% 的资产从未被查过备案**。`icp --limit 2000` 这条回填命令是离线手工跑的，
不在 scheduler 里，跑一次管 30 天。

### 1.3 第三层：查到了也不排除

```python
# triage.py:183
icp_registered = asset.icp_status == "registered"
...
if icp_registered and score < 80:
    reasons.append(icp_note + "（已备案，降为候选）")
    return TriageDecision(TIER_CANDIDATE, reasons, urgent)
```

备案只是"降一档"，而且 `score >= 80` 时连降都不降。设计意图是"黑产也会买壳公司备案"，
这没错，但它导致**备案在任何情况下都不可能把一个站移出视野**——这也是你感觉"查了等于没查"的直接原因。

### 1.4 第四层（最关键）：查错了对象

实测 `np4w53.cn` 与 `hksm38.com.cn`：

| 域名 | 页面写的备案号 | 页面写的标识码 |
| --- | --- | --- |
| np4w53.cn | `京ICP备202600001号-1` | `bm01000001` |
| hksm38.com.cn | `京ICP备202600001号-1` | `bm01000001` |

两个不同域名、两个不同 IP，**共用同一个备案号**。而且页面里有这段：

```javascript
var icpNum = String(Math.floor(Math.random() * 900000) + 100000);
```

**备案号是页面 JS 现算的**。这意味着：

- 查「`np4w53.cn` 有没有备案」→ 永远 `unregistered`，和亿万没备案的域名混在一起，零信息量；
- 查「`京ICP备202600001号-1` 属于哪个域名」→ 返回的不会是 `np4w53.cn`，**一击命中伪造**。

**备案的正确用法不是"查域名"，是"查页面自称的那个号"。** 这两种查法的检测力差一个数量级，
而现在代码只做了前者。

> 顺带一个副产品：同一备案号出现在 ≥2 个无关域名上，本身就是站群指纹，
> 不需要任何外部查询就能判。

## 4. 为什么白名单不能当过滤器

你原话是"其余的网站若声称'政府'当然就是诈骗了"。这句话本身成立，
但前提是**先有"声称"这一步**。如果做成"不在白名单 → 排除"，会立刻死掉：

| 站点 | 在 L1/L2 白名单 | 性质 |
| --- | --- | --- |
| 53kf.com | ✗ | 客服 SaaS，正常 |
| yige-tech.com | ✗ | 建站服务商，正常 |
| 39.net | ✗ | 健康门户，正常 |
| yanglaocn.com | ✗ | 养老行业门户，正常 |
| alibaba.com | ✗ | 电商，正常 |

**五个你点名或实测过的正规站，一个都不在白名单里。**

正确的因果链是：

```
词库/CT 召回  →  取证（移动端）  →  抽取"自称"  →  只有"自称政府/媒体"才查白名单
                                                      ↓
                                          不在白名单 → 冒充（高置信）
                                          在白名单   → 放行
                没有"自称" → 走原有的诈骗特征（APK、收款、群、承诺）判定
```

白名单是**验证器**，不是**过滤器**。它只回答一个问题："它说它是财政部，那它是不是？"

## 5. 移动端现状：做了一半

| 采集通道 | UA | 视口 | 代码 |
| --- | --- | --- | --- |
| 沙箱渲染（Playwright） | **iPhone** | 414×896 | `sandbox/web.py:309` |
| HTTP 采集（httpx） | **桌面 Chrome**（`UA_POOL` 随机） | 无 | `collectors/http.py:99` → `opsec.headers_for(url)` 默认 `mobile=False` |

实测 `np4w53.cn`：移动 UA **423 字**，桌面 UA **26 字**（"访问受限"）。15 倍差异。

沙箱已经默认移动，但沙箱是可选依赖（`install.sh` 里 `warn "未安装 playwright"` 后继续）。
**HTTP 采集器作为第一道，仍然是桌面 UA**——这就是"防爬站抓不到"的直接原因。

## 6. 建议架构

保留词库，但把它从"定罪器"降为"召回器"，另外补三层。

### L0 召回（词库，保留并扩）

- 词库继续用于 CT 流初筛，**不产生定罪分**
- 扩的方向：从"行业名词"转向"**动作 + 对象 + 承诺**"三元组
  （如"扫码"+"领补贴"、"下载"+"安装包"、"转账"+"安全账户"）
- 词库命中只决定"值不值得花一次渲染配额"

### L1 取证（默认移动端）

- HTTP 采集器的 `headers_for` 增加 `mobile=True`，或直接对 suspect 目标一律移动 UA
- 静态 HTML < 400 字时，强制升级到沙箱渲染（现在是有没有 playwright 决定，不是内容决定）
- 保留 UA 门禁信号本身：**同一 URL 桌面 26 字 / 移动 423 字，这个差异就是特征**

### L2 自称抽取（新增）

从渲染后的 DOM 抽四个字段：

| 字段 | 位置 | 用途 |
| --- | --- | --- |
| `claimed_agencies` | 页头、`©` 行、主办/承办/技术支持 | 与政府库比对 |
| `site_id_code` | `政府网站标识码[：:]\s*(bm\d{8})` | 伪造即 confirmed |
| `claimed_icp` | 版权行 `[\u4e00-\u9fff]{0,6}ICP[备证]?\d{4,12}号` | 反查归属域名 |
| `claimed_media` | 页头、版权行 | 与稿源名单比对 |

### L3 判定

```
if site_id_code and not host.endswith(".gov.cn"):        → confirmed（伪造标识码）
elif claimed_icp 反查域名 ≠ 当前域:                        → confirmed（伪造备案）
elif claimed_agency 在政府库 and 官方域 ≠ 当前域:            → watch（冒充 + 官方域名对照）
elif claimed_agency 不在政府库 and 形如"国家XX中心":         → candidate（虚构机构）
elif claimed_media 在稿源名单:                             → 降级/放行
else:                                                    → 走原有诈骗特征链
```

### L4 数据维护

- 政府库：Zenodo 快照，季度更新（或境内出口直连 zfwzzc 每日拉）
- 稿源名单：随网信办更新，半年一次；缺失的 URL 靠 10,000 域名库 + 人工补 31 家中央站
- 新闻库：**只做映射辅助，不做白名单**

## 7. 边界与风险

1. **事业单位、融媒体、公立医院不在政府库**。中国科协（cast.org.cn）、红十字会（redcross.org.cn）、
   地方融媒体 App 的 web 版都不在。它们若自称"XX市政府主办"会被误判。
   缓解：`claimed_agency` 必须匹配到**政府库中真实存在的机构名**才触发；
   自造机构名走 candidate 而非 confirmed。
2. **虚构机构识别不了**。"国家惠民补贴申领中心"这种库里没有，只能靠"国家/中国/全国 + 中心/办公室"
   的构词规则，这条会有噪声。
3. **稿源名单没有 URL**。329 个是靠名称模糊匹配出来的，会有漏（如"澎湃新闻"匹配到 thepaper.cn 没问题，
   但"上观新闻"可能匹配不上）。建议对 L2 白名单做一次人工核对，360 条量级可控。
4. **政府库是 2025 年末快照**。新设机构、撤并机构会失配，需要版本号与更新日期。
5. **`bm01000001` 之外还有别的标识码伪造**。规则是"任何 bm 码 + 非 gov.cn"，不针对特定值，
   所以覆盖完整；但要注意有些政府站用 `.cn` 老域名（政府库那 68 个），需要白名单兜底。
6. **移动端渲染成本**。每次渲染 3~8 秒，不能全量。必须由词库/CT 先筛，这反过来说明词库不能删。
