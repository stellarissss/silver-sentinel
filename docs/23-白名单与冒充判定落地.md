# 白名单与冒充判定：落地说明

> 对应调研：`20-词库识别机制重构调研.md`、`21-真实样本取证与ML可行性评估.md`、
> `22-白名单与政府冒充判定调研.md`。本篇只讲**改了什么、怎么用、边界在哪**。

## 一、一句话

词库继续负责「召回」，新增一层**身份核验**负责「定性」：

> 它说自己是财政部，那就去查财政部的官方域名是不是它。
> 对不上，就是冒充；白名单里根本没有它，就不该占队列前排。

这条路子绕开了词库的死结——骗子的话术词和正规站完全一样（补贴、养老、民政），
但**机构身份是唯一的**。

## 三、判定链路

```
取证（沙箱，移动 UA）
   ↓
claim.analyze_html(html, host)
   ├─ site_id = 「政府网站标识码：bm\d{8}」      非 .gov.cn → fake_site_id
   ├─ 页头/版权行里的机构名 → whitelist.agency_domains()
   │      官方域名 ≠ 当前域名 → impersonation
   │      库里没有 + 形如「国家XX中心」 → fabricated_agency
   ├─ host 在政府库/媒体库 → legit
   └─ 其余 → neutral
   ↓
reassess：fake_site_id 抬到 95 分（IMP-001，weight 96）
   ↓
triage：watch + urgent，理由写清「伪造 bm01000001」或「自称财政部，官方域名 mof.gov.cn」
```

### 为什么机器仍然不给 confirmed

既有约束是「confirmed 只能来自官方通报或人工复核」，因为那一档会直接进举报链。
伪造标识码虽然零误判，仍然只给 watch + 95 分 + urgent，人工点一下即可确认。
这样单条规则的 bug 不会直接产出一份错误举报材料。

## 四、抽取位置的规矩（这决定误报率）

只认两处，**且链接不算自称**：

1. `<header>` 内的文字；
2. 含 `© / 版权所有 / 主办单位 / 承办单位 / 技术支持 / 政府网站标识码` 的叶子元素；
3. 文档顺序前 12 个叶子块，长度 <100 字且**不含句读**（`，。；！？`）。

三条都是踩出来的：

| 版本 | 规则 | 踩到的坑 |
| --- | --- | --- |
| v1 | 正文前 300 字出现机构名 | 昆明理工、中南大学的「乡村振兴专题站」被误伤（正文引用农业农村部）|
| v2 | 页头 + 页脚全部文本 | 中国红十字会被误伤（页脚友情链接里有财政部/民政部）|
| v3 | 上述三条 + 剔除 `<a>/<nav>/<ul>` + 排除带标点的句子 | 32 个负样本 0 误报 |

## 六、命令

```bash
# 白名单规模、某个域名的判定
silver-sentinel whitelist
silver-sentinel whitelist --check www.mof.gov.cn np4w53.cn www.people.com.cn

# 单页自称分析（排误报最快的入口）
silver-sentinel claim https://example.com
silver-sentinel claim --html-file page.html --host example.com
silver-sentinel claim --text "审核机构 国务院办公厅" --host x.cn

# 备案号反查（抓伪造备案）
silver-sentinel icp --license 京ICP备202600001号-1

# 存活自检现在会报备案链路
silver-sentinel doctor
```

`doctor` 输出新增 `icp` 段与 `icp_warning`。**只报警不触发重启**——重启解决不了
容器没起，只会白白打断取证；但至少不会再出现「配过、后来悄悄失效、没人发现」。

## 七、白名单怎么更新

```bash
python tools/build_whitelist.py                      # 联网拉三源
python tools/build_whitelist.py --gov-csv x.csv --news-json y.json --cac-pdf z.pdf
```

- 政府库：季度。`zfwzzc.www.gov.cn` 境外直连会超时（reverse GFW），默认走 Zenodo 快照。
- 稿源名单：随网信办更新，半年一次。
- 媒体域名只能靠名称反查（稿源名单 PDF 没有 URL），匹配率约 44%，
  剩下的报纸/期刊/电视台本来就没有独立网站。

## 八、边界（必须知道）

1. **事业单位、融媒体、公立医院不在政府库**。中国科协（cast.org.cn）、红十字会
   （redcross.org.cn）都不在。它们自称「XX市政府主办」会被判 `impersonation`
   ——目前靠「只有自称的机构名在库里才算冒充」来兜，但它们若自称的是真实存在的
   地方机构，仍会误判。这类站点目前量很小，遇到就加进 `whitelist.ALIASES` 或人工 dismissed。
2. **虚构机构只能靠构词**。「国家惠民补贴申领中心」这种库里没有，只能匹配
   「国家/中国/全国/中央 + 中心/办公室/委员会/局」的构词，误报率高于前两条，
   所以只给 candidate。
3. **白名单不是过滤器**。53kf、易歌科技、39 健康都不在名单里，靠「不在名单就排除」
   会把整个中文互联网判成诈骗。它只回答「它自称的那个机构，官方域名是不是它」。
4. **备案反查依赖本地缓存**。`license_owners()` 只读 `icp_cache`（30 天），
   取证线程不联网。要让 `fake_icp` 真正生效，需要先跑一轮
   `silver-sentinel icp --limit 2000` 把缓存填起来。
5. **移动 UA 是默认值，不是万能**。桌面/移动文本量差异本身是特征
   （`np4w53.cn` 26 字 vs 423 字），已记进 `facts`，后续给模型用。

## 九、上线步骤

```bash
# 1) 升级并确认白名单加载（应看到 gov 13k / media 352 / agencies 16k）
pip install -U silver-sentinel
silver-sentinel whitelist

# 2) 让历史资产立刻享受新判定
#    重评会从已存的 page_html 补算「自称」，不必等 24 小时复访。
#    --retier 必须加：triage 默认只允许升级，不加的话历史上被误推到
#    watch 的政府站/媒体站降不下来。
silver-sentinel rescore --retier --limit 3000

# 3) 可选：把备案缓存填起来，让 fake_icp 生效（5 次/分钟，2000 条约 7 小时）
silver-sentinel icp --limit 2000 --workers 2

# 4) 自检：应看到 icp 段，且无 icp_warning
silver-sentinel doctor
```

第 2 步之后，`discovery_reason` 会直接写出判定依据，例如
「伪造政府网站标识码 bm01000001（该码只发给 .gov.cn），需人工确认」。

如果第 4 步出现 `icp_warning: 备案查询未配置`，说明 `SILVER_ICP_API` 为空——
这不影响冒充判定（标识码与机构名都不依赖备案），只影响「伪造备案号」这一条。
