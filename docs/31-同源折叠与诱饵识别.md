# 31 · 同源折叠与诱饵识别

> v1.14.0。两件事，一件关于**怎么看**，一件关于**看什么**。

## 一、为什么列表要折叠

上一版把 84 条涉老资产挖出来之后，列表页变成了这样：

```
2026年个人财政补贴申领   ← np01w13
2026年个人财政补贴申领   ← np02w21
2026年个人财政补贴申领   ← np03w37
... 81 行
```

这不是 81 个判断任务，这是**一个**判断任务被抄了 81 遍。

人工复核的时间应该花在「这批站是不是一伙的」，而不是「第 47 个域名和上面 46 个有什么不同」。
每多滚一屏，真正需要看的那条（比如某个伪装成正规养老院的站）就多一分被略过的可能。

折叠解决的是**注意力分配**问题，不是数据量问题。

### 分组依据按强度排

| 依据 | 键 | 为什么它够硬 |
|---|---|---|
| 同团伙 | `campaign:<id>` | 人工或情报源确认过 |
| 同证书 | `cert:<序列号+签发者+主体>` | CA 签的，不是页面写的。换域名不换证书 |
| 同收单端点 | `backend:<host>` | 换域名不换收单服务器，钱流向同一处 |
| 同模板 | `template:<归一化标题 + 正文长度桶>` | 标题逐字相同、正文骨架一致 |

**没有「同 IP」这一档**。共享主机上住着几百个互不相干的站，按 IP 聚合会把正常企业站和诈骗站折成一组——那是噪声，不是关联。

### 标题归一化

`2026年个人财政补贴申领` / `2027年个人财政补贴申领` 归一化后都是 `个人财政补贴申领`。
去掉年份、数字、标点、空白，再按哈希分桶。

三条护栏：

- 归一化后不足 4 字 → 不成组；
- 通用标题（`首页` / `登录` / `404` / `Just a moment` / `安全检测`）→ 不成组；
- 标题相同但一个是 12 字空壳、一个是 3000 字长文 → 分成两个桶，因为前者是诱饵、后者是内容页。

### 折叠不是合并

- `total` 是**视图条目数**，`raw_total` 才是原始条数。两个数都显示，否则用户会以为折叠把线索弄丢了。
- 每条资产仍然独立取证、独立定级、独立出证据包。
- 代表行取「档位最高、分数最高」的那条。
- 组里有诱饵时，组行上必须显示 `含 1 诱饵`——不能让它藏在展开后的第三行里。

## 二、暖阳那个教训：诱饵是证据，不是噪声

`26537.net` 首页写着「安全检测中心，请稍候」。正文里一个涉老词都没有。

按词表判，它干净；按行为判，它是几十个涉老站的入口。

之前的处理是「判不出涉老，留在 candidate 里」。**判断没错，结论错了**——它不是没有价值，
它是**分发渠道**。排除它等于放弃入口，而入口是会换地址的。

### 五种形态

| kind | 特征 | 该怎么用 |
|---|---|---|
| `interstitial` | Cloudflare / 阿里云 / 百度云加速 / 腾讯云 WAF 挑战页 | **不是目标站的内容**。按失败重试，绝不进证据链 |
| `security_check` | 短正文 + 核验措辞 + 有去向 | 诱饵。真实表单在下一跳 |
| `redirect_shell` | HTML < 3KB，只有一个 location / meta refresh | 诱饵。跨域才算 |
| `expired` | 「活动已结束 / 名额已满」+ 短正文 | **承认自己干过**。没有申领，哪来的结束 |
| `blank_shell` | 极短正文 + 建设中 / 维护中 | 壳。价值最低 |
| （蜜罐） | 隐藏陷阱字段、`navigator.webdriver`、反调试死循环 | 对方预期被扫描。这是**专业化**的证据 |

### 三条必须守住的边界

**1. 先排除基础设施。** WAF 挑战页的标题就是「安全检测」。不先识别出来，
每一批被墙的站都会变成「诱饵」，而拿 WAF 页判低分会把正常站永久沉底
（`capture_state` 一旦是 `captured`，就再也不会重试了）。

现在命中 WAF 指纹 → `capture_state=failed` + 冷却一天，证据（截图里那张挑战页）照留，
但这一趟不产生结论。

**2. 诱饵必须「短」且「空」。** 3000 字的《关于开展养老保险待遇资格认证的通知》里
写「系统将进行安全检测」是正常句子。长度是这里最重要的判据：真诱饵 12–180 字，
真公告 800–4000 字，`400` 字的分界线很宽，不会误伤。

**3. 诱饵只算「动作」，不凭空判涉老。** 受众指向仍然是必要条件。
否则每个用 Cloudflare 的站都会被算成涉老。

### 它怎么进判定链

```
诱饵页（无涉老词）
   ↓ decoy.action_evidence()
elder 的「转化动作」第四条证据
   ↓
受众(补贴) + 身份(身份证) + 动作(诱饵引导) = 3 → P0
```

按钮没点中怎么办？从运行时请求里取跨域 POST 目标（`api.php` / `submit.php`），
这些是现成的证据，不用再抓一次页面。同站提交不算。

### 分级上的处理

- 诱饵 + 已判涉老 → 不额外升档（已经够了）；
- 诱饵 + 未判涉老 + **有去向** → 至少 candidate，理由写「诱饵/分发节点」。
  冷存等于再也不看，而入口会换地址；
- 纯空壳无去向 → 不干预，让评分自然压到冷存。

## 三、落地

```bash
# 回填历史资产的分组键（只写 group_key / group_kind，不改分数与档位）
silver-sentinel regroup

# 顺带从证据仓读回 page_html / page_text，补算诱饵标记
silver-sentinel regroup --decoy --decoy-limit 800
```

接口：

```
GET /api/assets?collapse=1     # 默认。按 group_key 折叠
GET /api/assets?collapse=0     # 原始逐条
```

折叠后每组返回 `group: {key, kind, label, size, decoy_count, members[]}`，
详情页多一个「同源批次」卡片，列出同组的兄弟条目与其中涉老条数。
