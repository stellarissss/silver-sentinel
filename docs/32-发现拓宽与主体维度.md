# 32 · 发现拓宽与主体维度

> v1.16.0 部署后继续修正到 **v1.16.2**。这一版不是加功能，是修三个让数据
> 一直上不去的硬伤，并把其中「批量证书」那条按生产实测推翻重做了两次。
>
> 起因：连续运行一天后，捕获量与「广泛搜罗涉老诈骗网站/软件及其基础设施/主体」
> 这个目标差距很大，而且结论高度集中在一种类型上。先查数据，再动代码。

## 一、现场实测（2026-11-09 13:02 于生产库直查，非估算）

联网核实（公安部 2026-06-12 发布会，民政部/人民网同日转载）：涉老诈骗
**三大高发类型**是养老投资类、推销保健品类、冒充身份类；通报里被骗 100.97 万
的典型案例走的是「小众聊天 App + 扫码进伪装交易所」，**根本不是网站**。

> 所以「以仿冒政府网站为主」不是外面没有别的，是**判据和入口只认这一种**。

## 二、差距的物理根因

### 硬伤 1：`bulk_assets = 0` —— 信号选错了

v1.15 的批量证书主动扫描判据是 `len(obs.all_domains) >= 8`，即假设骗子把
几十个域名塞进**一张**证书的 SAN。现场 CT 轮询拿到的观测是：

```
michaelsaschalau.com  ["en-gh.michaelsaschalau.com"]
yl770.com             ["www.yl770.com", "yl770.com"]
cctv-bet.vip          ["cctv-bet.vip"]
```

现代站群用 Let's Encrypt / Google Trust Services **批量签发单域名证书**：
一个生成器几分钟注册上百个域名，每个单独签一张。证书 SAN 里再也看不到
「一批」。这不是阈值调低能解决的问题，是物理形态变了。

### 硬伤 2：图谱从来没读过正文

`graph/build.py` 的 `build_all` 预取证据时写的是
`evidence_map[...].append(ev.note or "")`，而 note 是
「页面正文 https://www.l2d5p.top/enter/index.html」——一句说明。
真正的正文在文件里（plain 或 vault 密文），`_attach_indicators` 抽的是
这句说明，自然一个联系方式都抽不到。线上 3386 条 `page_text` 证据，
图谱里只有 3 个微信节点。

### 硬伤 3：涉老判据只覆盖第三类里最窄的一支

`elder.py` 的 `_AUDIENCE` 是「养老/社保/补贴/康养/保健」。加上
`hard = identity or authority`（身份索取或权威冒用）这道定罪闸门后，
仿冒政府补贴站天然全中（伪造标识码 + 身份证表单），而投资盘、会销页、
医保冻结页一个词都不命中。89 条同一理由就是这么来的。

补充观察（非本版全部解决，但已定位）：
- certstream 单源 `certstream.calidog.io` 连续断流后静默 30 分钟；
- `nimbus2026` 12:50 报冻结，13:02 仍在跟——`_ct_manager` 检查间隔 1800s；
- 804 个「端口不通」的死域名占着取证重试额度。

## 三、v1.16 调整

### 3.1 批量单域名证书聚合（`discover/burst.py`）—— 前后两版

**初版（已部署 v1.16.0，实测失败）**：按
`(签发者, 命名签名, 证书签发 10 分钟桶)` 分桶，同桶 ≥ 8 个域名判为
一次性批量签发。取舍保留作踩坑记录：只收 `all_domains <= 2` 的单域名证书、
形态分 ≥ 0.60、冷却锁完整桶 key 防 CT 补历史重放、日预算 12 批且只在
真正采纳成功时扣减（避免清桶后才发现预算不足把线索丢了）。

部署后登录 `/api/discover/status` 读运行中引擎：

```
seen 10783  matched 91  queued 1
bulk_scanned 0  bulk_adopted 0
burst_batches 0  burst_adopted 0
burst {'seen': 10313, 'candidates': 97, 'bursts': 0,
       'batches': 0, 'open_buckets': 50, 'cooldowns': 0}
frozen 1
```

数据库 `discovery_source = 'ct_burst'` 的资产仍为 **0**。
`candidates 97 / open_buckets 50` 说明线索进了桶，但每桶平均不到 2 个，
永远凑不满 8 个。连续观察一小时更明显：`seen 71990 / candidates 920 /
open_buckets 308 / bursts 0`。

**二次离线重放（生产 CT 事件）** 找出了原因：

| 切分方式 | 结果 |
|---|---|
| `hot(>=0.60)` 单域名证书 | 221 / 4000 |
| 初版完整 key（签发者+签名+时间桶） | 190 个桶，最大桶 **6** |
| 签发者 + 时间桶 | 最大 8 |
| 签发者 + 签名（不按时间切） | 最大 **20** |

最大簇的签发时间：

```
('zerossl gmbh', 'com:3:digit') size 20
   yl8387.com 2026-09-15   yl5837.com 2026-08-21   yl2828.com 2026-09-17 ...
('google trust services', 'com:3:mix') size 13
   05cctv.com 2026-09-09   15cctv.com 2026-09-09   cctv668.com 2026-09-09 ...
```

> **现场数据推翻了初版的物理假设**：这些不是「一次性批量签发」，是同一个
> 生成器**长期运营**——固定字母前缀 + 变数字，域名一个一个注册、证书一张
> 一张签，签发时间散布 8~9 月两个月。按签发时刻 10 分钟桶分桶，从根上就
> 把长期族切碎了。线上反复出现的 `yl770.com`、`cctv-bet.vip`、`mz88` 正是
> 这几族，系统一直没把它们关联成一批。

**修正版（v1.16.1）**：主判据换成**前缀族** `fam:<前缀|TLD>`：

- `yl8387.com` → `yl|com`，`05cctv.com` → `cctv|com`（数字在前也认，两种
  命名模板归一到同族，否则冒充央视族会被劈成两半各凑不满 5 个）；
- 同族累计 ≥ **5** 个不同域名即触发；形态分门槛 0.55（族已有「前缀模板 +
  5 个同族」两道强约束，形态分只留余量；现场 5 族正例实测 0.64~0.92）；
- 初版时间桶判据降级为**补充** `win:<签发者|签名|10分钟桶>`，阈值仍 8，
  只在真是一次性批量提交时生效；
- 两条判据独立桶键，命中族的观测不再投进时间窗，不重复计数。

用 v1.16.1 真实代码重放生产库里 4128 条 `ct_poll` 事件：

```
family_key 命中 214 个域名 → candidates 241
bursts 5 / families 5 / windows 0 / seen_domains 25
  yl6738.com  yl7657.com  yl0147.com  yl6822.com  yl3827.com      (yl|com)
  mz643.top   mz905.top   mz479.top   mz920.top   mz6688.top      (mz|top)
  zk83.cc     zk89.cc     zk62.cc     zk78.cc     zk84.cc         (zk|cc)
  boc527.top  boc396.top  boc08.top   boc06.top   boc02.top       (boc|top)
  cctv48.com  cctv668.com 15cctv.com  05cctv.com  06cctv.com      (cctv|com)
桶键分布：win 84 / fam 73
```

实现是对的，5 族全部命中、零正常站误入。

**去重与不丢线索**（v1.16.1 一并修掉的实现漏洞）：

| 初版问题 | 修正 |
|---|---|
| 冷却期内 `return []` 直接丢观测；历史追平 25 个 `yl|com` 只采纳前 5 个 | 冷却/桶未满/预算耗尽都**只累积不丢弃**；冷却从 3600s 降到 600s，只负责限频，防重放交给域名级去重 |
| 文档承诺「族 + 域名双重去重」但 `_seen_families` 声明未用 | 每个桶键维护已采纳域名集合，CT 补历史 / 游标回退重放不再入池 |
| 日预算耗尽时 `_adopt_burst` 直接 return，观测根本不进桶 | 预算状态作为 `observe(adoptable=...)` 传入，`False` 时排队，额度恢复后第一批补采 |
| `stats["windows"]` 从不递增、`_offer(cooldown_key=...)` 是死参数 | 族/窗口分别计数，参数清理，`as_dict()` 增 `seen_domains` |
| `reason` 一律写「同签发者同时段」 | 按批次实际族键写「站群前缀族 yl|com」，证据链能说明依据 |

`limit` 截断后剩余域名留在桶里等下一批，不随 `clear()` 一起消失。

**形态边界（如实记录）**：`web2024.com` / `shop2025.com` / `mail2026.com`
这类「可读前缀 + 年份」形态分 0.36~0.44，被闸门挡住；但 `qq2024.com`
(0.69)、`abc123.com` (0.74) 这类短字母前缀会过闸。要凑够 5 个同族才触发，
后面还有涉老判定与人工复核，误判成本可控。这里刻意不加英文词白名单：那
等于把「不依赖关键词」换成一份要长期维护的词表，换个后缀就失效。

同时把 CT 冻结检查间隔从 1800s 缩到 180s，并把 `ct_burst`/`ct_bulk`
接进取证优先队列与复现保护（`await_capture`）。

### 3.2 涉老判据拓到三大类型（`elder.py`）

补齐公安部通报的三类特有话术（保本高息/原始股/养老床位、免费领鸡蛋/
专家义诊/高价保健品、医保冻结/转账验资/安全账户等），并新增只读的
`schemes` 分类标注（仿冒政府补贴 / 养老投资 / 保健品会销 / 冒充身份 /
民族资产解冻），用于统计与人工分组。

**两个防误判闸门一个都没动**：
- `audience` 仍是必要条件——否则博彩站、盗播站全会被算进来；
- `hard = identity or authority` 仍是定罪闸门——正规基金公司写「年化利率」、
  药店卖「保健食品」都不要身份证、不冒充部委，仍判不涉老。

新增反例测试覆盖的就是这条：正规基金页、正规药房页、泰文赌场页。

### 3.3 主体实体维度（`entities.py` + `graph/build.py`）

- 复用 `normalize.extract_indicators`（QQ/微信/手机/固话/银行卡/钱包），
  补上中文主体：收款人、开户行、公司名；统一微信号大小写便于跨站归并，
  过滤「张三/测试/示例」这类占位值。
- 取证时用**与涉老判定同一份正文**（首页 + 第二跳）抽实体，落
  `facts.entities`——落地页的收款信息常在第二跳，只看首页等于没看。
- 修 `build_all`：改读真正文（`read_evidence_text` 自动处理 plain / vault
  解密），把主体挂成图谱节点（phone / wechat / qq / bank_card / payee /
  bank / entity）。同一微信号或收款卡出现在几十个域名上，节点自然合并。
- 历史资产按每轮 60 个的节奏补抽并**写回 facts**，之后每轮建图零解密开销
  ——线上 1.8 万条 vault 密文不能每周期全解一遍。

> 主体比 IP 硬：证书会重签、IP 会换，收款账户不会天天换。

### 3.4 历史 CT 回放与写入加固（v1.16.2）

**为什么必须有回放**：把 3.1 部署后继续观察，运行中引擎
`seen 30173 / candidates 447 / open_buckets 186 / bursts 0` —— 一个族都没
触发。原因不是判据错，是**那 5 个族是 8~9 月的历史产物，证书早已签完，
实时 CT 流里再也不会出现**。库里存着 4128 条当时的原始观测，却从没被
关联过。光等实时流是等不来的。

`discover replay-ct` 把 `discovery_events` 里的 `ct_poll` 流水喂给同一个
`BurstDetector`，走与实时发现完全相同的采纳 / 去重 / 入库路径：

```bash
silver-sentinel discover replay-ct --dry-run      # 只看条数
silver-sentinel discover replay-ct                # 正式写库
```

- `DiscoveryEvent.raw` 是 **JSON 列**，SQLAlchemy 取出来是 dict 而不是字符串；
  第一版只按字符串解析，整批 4141 条被静默跳过、产出 0。解析器改成两种都认，
  并加了回归用例锁住。
- 回放是运维补漏，`unlimited=True` **不占当天的 12 批实时配额**。
- 幂等：`BurstDetector` 按桶键记忆已采纳域名，`_persist` 按 normalized
  跳过建重复资产，可重复执行（第二次 `created=0`）。
- 回放命中的多数是**存量资产**（`created=0`）。`_persist` 原来只更新
  `last_seen` / `meta`，注释却写着「和发现原因」——族依据因此一直没进
  人工审阅视野。改成追加式写 `discovery_reason`（`旧结论；站群前缀族 …`，
  去重 + 截长，不覆盖人工结论），并给这些资产补 `await_capture` 保护。
- 批次流水原来整批复用触发那一张证书的 `CertObservation`，导致
  `raw.domain` 与 `value` 对不上，还让 25 个域名共用一个 fingerprint、
  被 `_cert_clusters` 误判成「同证书团伙」。改成每行记自己的域名；
  **多 SAN 批次保留 fingerprint**（确实同一张证书），**单域名批次清空**。

**锁冲突（既有问题，已缓解未根治）**：部署前后日志都有
`database is locked` 并伴随「发现批写入失败」。根因是 WAL 下「先 SELECT
再 autoflush 写入」撞上并发提交会立刻返回 `SQLITE_BUSY_SNAPSHOT`，
`busy_timeout=30000` 对这种情况无效，只能整体重跑事务（日志里的
`Query-invoked autoflush` 正是特征）。两处改动：
- `_flush()` 对 locked 整体重试 3 次，发现线索不再一次失败就丢；
- `core/replica.py` 快照改用 `mode=ro` 只读源连接 + `backup(pages=512,
  sleep=0.01)` 分批复制，避免 4.4G 库一次 backup 长时间占住源库读快照。

实测频率从 **12 次 / 2 分钟降到 7 次 / 3 分钟**，但没有清零——建图、
vault 密文化等长事务仍会造成瞬时竞争，列为下一版方向。

## 五、仍未解决（下一版方向）

1. **软件侧**：6099 资产里只有 1 个 APK。公安部通报的百万案例走 App + 扫码，
   需要接 APK 分发链、短链展开、应用市场与包名聚类，不能只盯 CT 域名。
2. **渠道**：97% 涉老来自一个种子，说明外部情报源（urlscan 仅 33 资产）
   产出太弱；需扩多源并按「线索 ≠ 结论」的原则全部自行取证复核。
3. **取证预算**：804 个「端口不通」死域名占着重试额度，需要与强线索
   分级排队，否则新采纳的批量线索排不上取证。
4. **SQLite 锁竞争**：`_flush` 重试与副本只读分批已把频率压到
   7 次 / 3 分钟，但建图 / 密文化长事务仍会撞 `SQLITE_BUSY_SNAPSHOT`；
   需要把大事务拆成多个小提交，或把写侧统一到单一队列。
5. **实时发现与历史回放打通**：把 `replay-ct` 挂进周期任务，或让 CT
   follower 启动时回退游标，否则新出现的长期族依旧要等运维手动补漏。
6. **族内关联还没上图**：族依据目前落在 `discovery_reason` 与事件流水里，
   25 个域名在图谱 / 前端折叠中尚未连成一组。下一步把族键写进
   `group_key` / 图谱节点，配合已有的同源折叠展示。
